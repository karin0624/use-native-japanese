# 未使用の人手訂正対を全文から確認する

## この工程で決めること

[用法群内の平均](frame-support-check.md)では、一名詞への過剰な依存が弱まり、通常使用の一部の相対的な支持も残った。機関車の通常使用が低支持になる例や、一語frameへの依存は残る。この構成を固定し、**既知の誤り位置を与えずに、別の人手訂正例の使い方と原位置を取得できるか**を確認する。診断9例で閾値を合わせたり、残った例への補修を加えたりしない。

対象は事前選択済みのTeacher Corpus 9対、原文と訂正文の計18全文。9group・7型であり、9種類の独立現象とは数えない。選択時に解析・照会・採点を行っていない。元の人手訂正と、当方による対象適合の選別を区別し、訂正文全体を完全正用goldにはしない。元データは[Teacher Corpus](https://doi.org/10.5281/zenodo.4276130)（CC BY 4.0）、固定ファイルはGit外の`lexical-validation-inputs-20261022/selected-pairs.jsonl`、SHA-256は`dd79c747556b41444e22d9274328b604de6bb96fe6aa8493e9cadd22b3fc3452`。

## 生成と照合

生成側の入力をIDと全文だけの18文書へ分ける。人手の訂正位置、比較位置メモ、読みのヒント、期待する語・格は渡さない。全文から公開解析の全対象を生成・保存した後で、原注釈と結合する。対象箇所だけの追加照会はしない。

- 解析は採用済みのJuman++ → native KNP → rhoknp。固定binary・辞書・`-case -no-probcase -no-use-cv-cf -tab -para-scode none`を再利用し、公開同形候補を保持する。原文位置は既存の文字対応処理で保存し、不一致を言語規則で直さない。
- `PasExtractor.is_pas_target(verbal=True, nominal=True)`の対象に、`get_all_arguments(relax=False)`を使う。同じnative出力の述語と元項を読む。旧KWJAの7格制限や境界一致の前提は使わない。公開`case_mapping_key`と`Argument.case`を保存し、表層助詞から格を推測しない。
- PAS対象とbridging対象は重なり得るため、bridgingの印だけでPASを捨てない。PAS対象でない基本句の関係は別に保存する。本文外の項、未取得項、rawの未充足格は照合済みの関係に数えない。
- 語彙の接続は[現在の契約](normalization-connection.md#接続条件の訂正)を再利用する。述語F・条件付きN・公式NPAのC、元項自身の主辞’→主辞→Cを保持する。用言型と非用言型が共存する場合は公開consumerと同じ用言優先とし、旧接続のNPA優先を移植しない。態や格を能動形へ独自変換しない。
- 同じ原述語・型・格で、既存readerによる直接観測と通常frame内UNI平均を得る。一般化属性、未接続`?`、取得不能は前工程どおり別状態にする。直接観測は近傍計算を省略するが、誤用の非指摘に至る経路として評価から除かない。

新入力の名詞に公開の表記候補が複数ある場合は、各入力候補についてframe平均まで独立に計算し、候補・frame・採用照会間の最大を返す。用例一語ごとに都合のよい入力候補を選ばない。入力候補、不能、最大を与えた候補を残し、一意に同定できた語とは呼ばない。用例側の同一IDのaliasは、前工程どおり一票内で平均する。

## 評価と判断

局所対照では、原注釈と比較位置に対応する同じ出現の語・格・原位置を取得できたかを先に確認し、その後に原語と訂正語の直接観測・連続支持値・支持元を比較する。対象関係が列挙されない、公開値が元の語と合わない等の場合も固定9対の分母に残す。人手の広い訂正範囲と重なっただけで成功にはしない。

同じ18全文の全候補から、直接観測、計算可能、不能、未充足の数を報告する。支持値の全境界における対象箇所への到達と全文への指摘件数を保存し、よい境界だけを選ばない。訂正側や未注釈位置への指摘負担は、真の誤警告率とは呼ばない。LLMの判定を新しい人手正解にせず、追加の人手確認をこの工程の前提にも置かない。

全対照の分離を要求せず、どの誤用を拾える根拠が得られ、どの通常使用も弱まるかを具体的に判断する。直接観測による見逃し、関係の脱落、資料不足、名詞表現、群内の希釈を区別する。結果を見て入力を差し替えたり、例文別の除外を足したりしない。一般文・技術文への性能は、この短い18全文だけでは未確認であり、次に既存資料の在庫確認と独立入力の固定を行う。

## 実行範囲

実装はGPT-6.1-solの担当がscratchへ置く。既存の解析接続・型付きreader・ID逆引き・名詞表現・frame集約を再利用し、fresh contextで単純さと入出力契約をレビューしてから、一周する。必要IDだけを保存する既存の逆引きを一度行い、全量の別DBや新モデルを作らない。

18全文の全候補を扱い、候補数による打切りは加えない。解析から比較まで起動込み10分、出力追加量500MiBを上限とする。超過・失敗時は元入力と完了段階を残し、未完了を支持なしへ変えず、原因確認後に工程を見直す。大きな固定metadataの反復保存はしない。

生解析・stderr、語と格の公開値・原位置、照会と直接観測、frame別の支持と分母・不能理由、後段の注釈対応、時間・RSS・資源identityを保存する。処理済み段階は失敗時も再利用できるよう別出力にし、単純な段階分割以上の再開基盤は作らない。原文・モデル・辞書はGitへ含めず、製品閾値・訂正候補・製品実装はこの確認と分ける。
