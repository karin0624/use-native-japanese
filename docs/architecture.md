# 用法の証拠を位置付き判定へ渡す構成

目的は、自由文にある誤った日本語を位置付きで指摘すること。以下はそのために選んだ**検証用の一構成**であり、製品性能の採用判断はまだ行っていない。必要な情報から方式を選び、保存・接続部品の実装を始める。候補の解析器を順番に動かして設計を決める工程には戻らない。

## 必要機能から方式を選ぶ

| 必要な情報・処理 | 対応する原理 | 選んだ役割分担 |
| --- | --- | --- |
| 原語、関係、助詞・補語等が同じ出現で結び付いたこと | 語彙を保持した構文的n-gram | 公開依存木の連結部分構造。元の解析結果に日本語の結合・修復規則を足さない |
| 原語の使用実績と、参照資料の疎さの区別 | 条件付き共起と周辺分布 | 同じ比較条件の原語件数・条件件数・周辺件数を別々に保持する |
| 未見の名詞との組合せを一般化する材料 | 実例に基づく選択選好 | 他の原語・構造を固定し、実在する名詞候補との類似度と出典を返す |
| 参照用例が入力の意味に適用できるかの材料 | 同一語の文脈比較（Word-in-Context） | 入力と参照の両方を文脈表現へ写す。入力側の表現だけで参照側の語義を推測したことにしない |
| 証拠の組合せから指摘位置を決める | 文脈・統計を用いる位置単位の誤り検出 | 既存の位置教師で分類器を学習する。用例未観測や高い意味類似度を単独の判定規則にしない |

[Goldberg・Orwant 2013](https://aclanthology.org/S13-1035/)は分岐を含む構文的n-gram、[Erkほか2010](https://aclanthology.org/J10-4007/)は実在の対象からの一般化、[WiC](https://aclanthology.org/N19-1128/)は同じ語の二つの文脈を比べる課題に対応する。これらの論文が、この組合せによる日本語誤用検出を実証したという意味ではない。

## 局所構造と原文の契約

正本には全文、文字位置、既存解析器の全token、lemma、UPOS、形態属性、head、dep、文境界を保存する。解析器・辞書・schemaの版も固定する。GiNZAの公開依存木を使う理由は、必要な語・機能語・分岐が元のgraphに残るためである。以前の独立arc集計で消えた共同出現を、解析器の独自補正で作り直すものではない。

比較単位は、文内の基本依存木にある2〜4 nodeの弱連結な誘導部分構造とする。原文順に並べた各nodeの`(lemma, UPOS)`と、局所番号による有向depを一つのkeyにする。絶対位置や字間距離はkeyにしない。同じ文に同じlemmaの述語が二つあっても、別のhead出現の関係を合成しない。

4 nodeは計算量を制限する初期上限であり、全ての構文・用法を表せるという意味ではない。範囲外の修飾・照応・談話、keyに入らない形態属性の違いは未評価である。列挙予算を超えた部分結果を完全集合にせず、未完了を返す。例文に合わせてnodeを結合・補完する処理は作らない。

3/4 nodeの集合列挙には[igraphのRAND-ESU](https://igraph.org/c/html/latest/igraph-Motifs.html#igraph_motifs_randesu_callback)を使い、2 nodeは公開edgeの両端を使う。原文順を同一性に含めるので、比較時の対応は一意であり、汎用graph同型探索を追加する必要はない。igraphはGPL系で、ローカル利用と組み込み再配布の条件を区別する。

## 原語件数と一般化を混ぜない索引

同じUPOS・dep・相対順序を持つ形を`S`、全原語を固定した構造を`F`、判定位置を`t`とする。

| 値 | 同じSの中で固定する語彙条件 |
| --- | --- |
| `c` | 全slotの原語 |
| `r` | t以外の全slotの原語 |
| `m` | tの原語だけ。他の全slotは自由 |
| `N` | 語彙を全て自由にする |

`c, r-c, m-c, N-r-m+c`が同じ出現母集団を分ける。記事数は異なる測度なので、この式には代入せず、c/rの資料支持量として別に保持する。同じ記事の複数箇所を複数記事に数えない。

全観測keyを先に集約し、完成索引だけから照会する。構築にはSQLite、完成時の等価検索には[marisa-trie](https://github.com/pytries/marisa-trie)と固定幅の値配列を使う。cold queryで毎回コーパス全体を探索しない。未見keyを0件と扱えるのは、同じschema・資料範囲の構築完了が確認された場合だけである。未完了、版違い、shape未観測、r未観測を区別する。

名詞slotを一つ自由にした同じ条件から、実在名詞・件数・記事数・出典を取り出す。原名詞自身は直接支持として分ける。近い実在名詞の上位3候補を、類似度とその用例を対応させて保持する。候補平均で少数用法を埋めず、一候補の高い類似度を正用保証にも変換しない。動詞・形容詞の類義語を経由して原語を肯定しない。

索引は本文・位置へ戻れる引用を持つ。全候補を返す費用は候補数に比例するため、key検索が速いことだけで全文検査の速度を主張しない。途中打切りを行う場合は、その候補最大値を全体の最大値と呼ばない。

## 入力だけでは不足する文脈情報

同じ原語Fと同じ件数でも、参照が別の意味で使われていれば適用できない。この差を入力BERTだけから復元する構成は採らない。

検討する拡張は、同じ凍結encoderで参照の出現表現を前計算し、同一lemma/UPOS内の複数の代表表現へまとめる方式である。[Wadaほか2022](https://aclanthology.org/2022.coling-1.366/)の用例別表現・複数prototypeの原理を参照する。最大4代表は語義の正解数ではなく量子化の上限であり、少数用法の併合が残る。代表を各nodeで独立に組み合わせず、Fの同じ実出現で観測された代表の組を保持する。

原語の共通成分を抑える同一lemma内の中心化、他の代表との比較を使うが、原語自身が文脈表現を誘導する影響を完全に除去できるとは主張しない。原語未観測の場合に、別語の文脈支持を直接支持へ昇格させない。全tokenごとのmask再計算は、オンライン経路へ導入しない。

この追加は現在も検証対象である。必要な文脈差が代表への圧縮で消える場合や、前計算・容量が成立しない場合は、入力側の表現だけで補えると読み替えず、圧縮・保存方式へ戻る。

## 指摘へ結び付ける仮説

初期の一案は、凍結Tohoku BERTの位置表現、上の原語支持・名詞候補・参照文脈・資料状態を、既存の`HistGradientBoostingClassifier`へ渡す。全位置を扱い、fragmentの低支持を全node共通の誤りラベルにしない。離れたnodeの間の文字も自動的に誤り範囲へ含めない。

可変数のfragmentは、サイズ2/3/4ごとに「直接記事支持が強いもの」「同じ条件で原語選択が弱いもの」「名詞一般化の支持候補があるもの」の対応付きレコードを残し、全体の観測・不足件数を併記する。この要約で必要な希少支持が落ちるなら、分類器の調整では直らないため要約を見直す。全fragmentを無損失に保持したとは呼ばない。

既存の全非空誤りspanを位置教師にし、非語彙誤りを負例にしない。未注釈位置と補助訂正文には残存誤りがあり得るので、出力scoreは真の誤用確率ではない。学習者・同文groupを分離した固定splitを維持し、token行の無作為early stoppingを使わない。学習者文の評価値をAI技術文の性能へ読み替えない。

この構成でも「意味が通るが原語選択は不自然」と「稀な正用」が分かれるとは未実証である。全体scoreだけで採否を決めず、外部情報がどの区別を追加し、どこが依然同じ入力になるかを追う。

## 次の判断と終了条件

1. **保存・索引の成立。** joint、同じ母集団の分母、記事支持、原文位置が保存・再読込後も一致することを確かめる。既存の完成解析1,000段落からは約102万fragment、固定1%参照全体へは約7,060万出現と外挿されるが、distinct key数は未測定。まずこの固定標本でdistinct数・圧縮後容量・構築peakを測り、資料の低頻度部分を勝手に捨てずに全量へ進めるか判断する。新しい解析器の比較はしない。
2. **参照の文脈差。** 同じ原語の用法差が追加表現へ届き、代表化で必要な差を消さないか確かめる。これは意味表現の機構確認であり、誤用検出性能の評価ではない。
3. **検出への寄与。** 一構成の学習後、同じ警告負担で外部情報の有無だけを比較する。未見原語、低い原語支持と高い意味類似、資料不足を分け、変化の原因を確認する。その後に保留test・実際の利用文・常駐遅延・位置・textlint接続へ進む。

実装完了後はfresh contextで、不要な抽象化、日本語規則の紛れ込み、過剰なテスト、既存ライブラリで置換できる箇所をレビューする。訂正案は検出と独立した任意機能であり、用例lemmaをそのまま活用済みの修正文として提示しない。
