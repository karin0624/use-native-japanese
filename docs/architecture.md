# 現在の解析・照合構成

目的は、AIが出した日本語から「重複を畳む」のような用例に裏付けられない語の使い方を位置付きで指摘すること。今回の完成条件は、検証した方式へ所定形式の情報を追加することで性能を改善でき、容量・処理費用を現実的に増やせることを示すところまでである。全ケースの正答や未収録用例の解消は求めない。固定した判断と検証範囲は[実装・完了確認](incremental-runtime.md)にまとめる。

## 原文から同じ出現の語と関係を得る

Juman++で形態素解析し、KNPの標準確率経路で構造・格関係・語の正規化を得る。rhoknpとcohesion-toolsから公開された述語項関係と原文位置を読む。形態素、助詞、複合述語の解釈を独自の日本語規則で補修しない。

活用や丁寧さと、格関係の表記は別の情報である。たとえば「つける／つけています」は基本形へ正規化する一方、どの項とのどの格関係かは同じ出現の格解析から得る。表面の助詞を独自対応表で置換しない。引用用の述語句全体と、照合用の正規化された語を区別する。

照合する述語候補は公開値から取得し、動詞・形容詞を類義語へ置き換えない。KNPに追加した出力は既存の非CV見出し生成処理を公開するもので、文法や格解析の変更ではない。相等を含む候補と基本形候補の接続条件、受動等を無条件で能動へ戻さない扱いは[解析器との接続](parser-connection-check.md)に定める。

項は公開された主辞等の正規化表記と位置を使う。ただし正常終了でも、形態素の分割により原文の語を失う場合がある。「コントローラー」が「コント」と「ローラー」に分かれ、項が「ローラー」となる例を確認している。位置の一致だけで語の保持を保証したと扱わない。

KNPが文単位で依存解析へfallbackした場合は、その文を格解析不能として残す。正常な前後文の処理は続ける。終了異常、未完出力、原文との不一致は同じ扱いに緩めない。

## 既成の用例資料へ照合する

参照には取得済みの京都大学格フレームを用いる。入力と同じ述語表記・述語型・格の欄を読み、その項の実語IDが観測されているかを調べる。辞書のCDBにはpure-cdbを使い、公開形式の読取りと変換を実装する。既成資源を使うため、利用者が全文コーパスを毎回解析・保存する構成ではない。

直接の観測があれば、名詞一般化による比較を省く。その結果は「参照資料で観測済み」であり、文脈中の正用証明ではない。用例のある正しい表現同士の意味差は今回の検出対象に加えない。

観測されなかった場合も、資料の未収録、入力解析の不足、語の組み合わせの不自然さを同じ原因と決め付けない。辞書や解析の異常を、用例の未観測へ読み替えない。

## 名詞の一般化による支持を計算する

直接観測のない関係について、**述語・型・格を固定した通常の格フレーム内**に現れた名詞と、入力名詞のベクトルを比較する。既存の圧縮fastTextモデルとライブラリを使い、入力文をLLMへ送って正誤を決める構成にはしない。

同じ実語ID列の表記候補のベクトルを平均し、比較可能な実語ID列を一票ずつとしてフレーム内で平均したμを作る。μの方向と入力名詞とのコサイン類似度Dを計算し、フレーム・入力候補間の最大を取る。実語平均の途中では再正規化しない。辞書が明示した和フレーム、頻度重み、上位語だけへの切詰め、語別の例外は使わない。旧raw平均と群方向の違い・限界は[全文確認](full-text-support-check.md)末尾にある。

比較不能な語や表記は支持ゼロへ置換せず、比較できた件数とともに残す。最大を取った候補が、入力で意図された一語だとは限らない。支持値は正用確率・誤用確率ではなく、この参照と比較方式による値である。

## 指摘判断と利用者への接続

既使用の診断資料から暫定境界D < 0.35を固定した。直接観測がなく、比較可能な用例群からの支持が境界未満の関係へ指摘を返す。全未観測を指摘する方式ではなく、値も正誤確率や一般的な日本語の境界ではない。比較不能と原注釈の対象範囲を保ち、固定後の独立適用と追加前後で検証する。

指摘は原文中の対象位置へ返し、離れた名詞と述語の間を塗り潰さない。Python API・JSONLワーカーは同じ解析器と参照を保持し、textlintへUTF-16位置で接続する。rhoknpの既存常駐I/Oを使う。訂正候補は、妥当性を確認できた場合に追加する任意機能とする。

## 用例の追加と規模拡大

既存解析から得た正規化用例を、出典付きJSONLで受け入れる。SQLiteの完全一致索引へ追加し、同じ述語・型・格・名詞の観測があれば直接支持として使う。元の配布CDBや一般化群は書き換えない。全出典を保存する一方、通常検査で返す根拠は代表1件とし、同用法の出典が増えても全件を返さない。

追加する用法E、出典対応R、文字列の総量Lに対して保存はO(L+E+R)。全名詞対や入力×参照の行列を作らない。既存CDBのaliasは逆引き表を一度用意し、群のμは必要時に一度計算してO(Gd)で保存する。複合aliasの組合せを逐次集約し、組合せ自体は保存しない。ただし初回構築の組合せ数に依存する時間は残る。固定辞書の準備費用、追加用例の費用、常駐時の費用を分けて測る。

## 資源と過去の試作

原文、辞書、モデル、派生索引はGitへ含めない。導入時に固定した資源とhashを照合し、実行時の構成確認と区別する。再現手順は[セットアップ](setup.md)にまとめる。

初期のGiNZA部分構造索引、文脈モデル、HGB分類器等は採用済み製品の構成ではない。その計測と制約は[初期検証](minimal-validation.md)とGit履歴へ残す。既に実装したことを、現在の実行経路や依存へ残す理由にしない。
