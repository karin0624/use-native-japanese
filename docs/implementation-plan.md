# 目的から決める設計と検証

目的は、AIが出した誤った日本語をリアルタイムで位置付き指摘し、可能なら訂正案を出すこと。技術文・一般文の語彙選択と不自然な組合せを重点にする。既存手法を順番に動かして採否を決めず、必要な情報から一つの構成を設計し、その判断を変える問いだけを検証する。

現在は**構成に必要な情報を確定する工程**であり、製品方式は未採用。BERT単体学習と参照全文解析は停止中。調査・固定資料・完了した測定・接続部品は引き継ぐ。

## 問題を分ける

「専門用語」「未見表現」という区分だけでは、次の問題を区別できない。

| 問い | 必要な情報 | 混同してはいけないこと |
| --- | --- | --- |
| 名詞は何を指すか | 原名詞、既知の意味、文中の定義・修飾・対象の状態 | 造語の名前を知らないことと、対象の意味が分からないこと。索引外・低頻度だけでは造語と判定できない |
| その対象に原文の動詞をどう使っているか | 原述語の内容、対象との関係、使い方を限定する文脈 | 「重複」と「畳む」をそれぞれ知っていることと、「重複を畳む」という使い方の適否 |
| その使い方にどんな用例があるか | 原語の結合と、原述語・関係を固定した実在の対象群 | 原語の実例、似た対象からの一般化、意味が通じることは異なる支持 |
| 判断する材料があるか | 解析・対象意味・比較条件・参照用例それぞれの取得状態 | 資料不足、対象意味の不明、用例がある条件での原語未観測、誤用 |

造語にも文中の説明があれば対象を推定できる可能性がある。説明がなければ不明を残す。単語ベクトルが生成できたことを、対象の意味が判明したことにしない。名詞全体を指摘対象から外す設計でもない。

「その対象にその操作が意味的に可能か」だけでは、慣用的な語の選択を検査し切れない。意図を理解できる表現にも語彙誤用はあり得る。対象の意味推定に成功しても、原文の動詞の使い方の検査は必要である。

## 一つの構成と、各部分の役割

**既存解析で原文の関係を位置付きで読み、原語の使用実績・同条件での対象適合・資料の充足を別々に取得して、局所指摘へまとめる。** それぞれの情報を独立した検出器にして警告をOR/ANDする構成ではない。

1. **原文位置と使い方を保持する。** 形態素、述語、関係は既存解析器の公開出力に委ねる。原語の代わりに類義動詞を問い合わせない。必要な情報を出力しない場合に、助詞の解釈や複合述語の結合を自作して埋めない。全入力を受け取り、解析できない位置も未評価として記録する。
2. **用例の結合と、対象群を残す。** 原述語・公開関係を条件に、観測された対象名詞、件数、記事支持数、出典・位置を保存する。原語ペアの支持、述語側の対象分布、名詞側の使用分布を別に取り出す。件数だけへの圧縮で、何が対象に使われたかを捨てない。
3. **名詞側を一般化する。** 原述語・関係を固定したまま、入力対象と実在対象群の適合を既存の分布的手法で推定する。対象表現の根拠・不明と、用例との適合を分ける。動詞の類似性を経由して別の動詞の用例で原表現を肯定しない。文脈表現を使う場合も、「畳むと書いてあるから畳める対象だ」と自己支持していないかを確認する。
4. **指摘へまとめる。** 原語の支持、一般化による適合、資料状態から原文位置を判定する。位置教師はこれらの使い方を学ぶために用い、語彙知識や参照側の分布を少量教師から新たに再構築させない。件数・類似度をそのまま誤用確率と呼ばない。判定器の式と入力は、前段の情報契約を確定してから固定する。
5. **訂正候補を別に扱う。** 指摘した位置に対し、実例と出典を伴う候補を取得する。候補の頻出や存在だけで原文を誤用としない。意味や活用を確認できない候補を完成した置換文として提示しない。

入力の文脈表現は、対象や使い方を理解する補助になり得る。外部用例は、その原語を実際にどう使ったかを提供する。位置教師は指摘の判断を与える。この役割分担を維持し、既存モデルが全てを暗黙に知っているという前提へ戻さない。

### 一般化の最小案

最初に確かめるのは、**固定した原述語・関係の実在対象群から、入力名詞に近い支持候補を取り出す構成**である。`q`をその比較条件、`A(q)`を観測された対象名詞集合、`e`を既存の名詞ベクトルとすると、候補は`cos(e(n), e(a))`が大きい実在名詞`a`から取得する。原語`n`自身の実例は直接支持として別に数える。ベクトルや対象集合がない場合は、類似度ゼロではなく取得不能とする。

最も近い対象との類似度は、支持候補が存在するかを見る特徴にする。候補名詞・類似度・その条件での実在記事数・引用元を対応させた少数の候補も残し、最大値だけへ圧縮しない。候補数の上限は保存・処理量とともに固定する。別の対象群が多数あることで、少数の正当な用法が平均の分母に埋もれる構成を避けるためである。特定分野の使用であること自体を減点しない。

これは「近い一語があれば正しい」という判定ではない。話題が近いだけの語、広く何にでも近い語、解析の誤り、別義の実例による誤支持が残る。原語支持、各候補の支持量、全体の候補数を別に保持し、適合の最大値を正用保証へ変換しない。少数の実例を支持材料にすることと、その一例を絶対視することを分ける。

この計算だけなら全文encoderは必須ではない。静的表現では同じ名詞の異なる意味・状態が同じになるため、必要な区別がその表現にない場合は、定義・修飾等の文脈情報を使う構成へ戻る。造語の意味を全て推定し切る機能を、新たな開始条件にはしない。ベクトルの登録語・subword推定等の来歴は保持するが、登録済みを意味理解の保証とも、未登録を造語の証明ともしない。

Erkの一般化原理を参照するが、この最大類似度による候補取得をErkの加重平均式の再現とは呼ばない。式の違いと、残る失敗条件は[研究記録](prior-research.md)に明記する。

## 学習前に確認できた情報の欠落

### 件数だけでは対象への一般化ができない

同じ述語・関係の件数が等しくても、実際の対象が機械類の資料と、人間の資料とでは新しい対象への適合は異なる。原語件数・周辺件数・欠損だけから、この違いを復元できない。

このため、検討した「入力encoder＋raw arcの件数＋小さいMLP」のまま学習へ進まない。一般化に必要な実在対象群を欠いたまま、1,054の語彙spanで補えるという根拠はない。文脈表現と情報融合の研究があることと、この欠落を解消したことは別である。

### raw arcの件数と、使い方の支持は一致しない

GiNZA 5.3.0／ja_ginza 5.3.0／spaCy 3.8.16の公開出力を、既存例と必要な対照26文で確認した。正誤の評価ではなく、索引キーが情報を区別するかの点検である。

| 入力の違い | 両端lemma・depだけの索引で保持する情報 |
| --- | --- |
| 重複を畳む | `畳む —obj→ 重複`を保持する |
| ファイルを削除する／統合する | `削除／統合 —obj→ ファイル`を区別する。サ変全てが「する」になるわけではない |
| 精度が高い／大きい | `高い／大きい —nsubj→ 精度`を区別する |
| 精度を高くする／大きくする | 両方`する —obj→ 精度`になる。形容詞は別arcに残るが、三者の同時出現件数がない |
| 会社に勤める／で勤める | 両方`勤める —obl→ 会社`になる。助詞は別arc |
| 友人に話す／について話す | 名詞・述語arcが同一。case子のlemmaまで加えても「に」で一致し、fixed子が異なる |

入力側の全arcをMLPへ渡しても、参照側で捨てた同時出現は取り戻せない。必要な区別を持つ既存の解析単位か、参照中の出現単位を保持する必要がある。[KNP・rhoknpの既存点検](parser-investigation.md)では用言代表表記・表層の係を取得できたが、同梱辞書等の利用条件は未確認であり、製品依存には決定していない。

表層格と意味役割は同一ではない。完全な意味正規化を必須条件にもせず、既存出力が保持する区別と失う区別を明記する。解析できる少数例だけへ検出対象を狭めない。

## 次の工程へ進むための情報契約

学習や全量解析の再開前に、次を一つの具体案へ固定する。

- **比較条件:** 既存APIのどの述語表記・関係・対象表記を使うか。原文表層・原文位置は別に保持する。欠けた属性を別の語の用例で補完しない。
- **件数と分母:** 同条件の原語ペア件数、述語側の全対象件数、名詞側の同関係使用件数、各記事支持数。記事支持は固定snapshot内の異なる記事ID数。ゼロ件、条件自体の未観測、取得不能、キーで区別できない状態を分け、定義できない比率をゼロへ変換しない。
- **一般化:** 条件付き対象集合、入力対象の表現、候補の取得方法と上限、利用可能性。取得できる事実として、登録語ベクトル・subword生成・文脈利用・取得不能を保持する。「対象の意味を正しく理解したか」はそれだけでは判定できず、機構点検の読解判断とruntimeの観測状態を混ぜない。類似度は言語的支持の一部であり、慣用的正しさの確率ではない。入力語を事前登録したcacheを、任意の造語を扱えるruntimeと呼ばない。
- **教師:** 原注釈の全ての非空誤りspanと重なる位置を誤りの正例にする。非語彙の既知誤りを正用へ反転しない。その他の位置と補助訂正文は不完全な負例。曖昧な整列・特殊tokenは無視し、欠落位置を隣の誤りへ拡張しない。語彙誤用を別集計し、同じ原語ペアを学習中に見たかも記録する。原注釈を書き換えない。
- **実行単位:** textlintからの段落・見出しを独立した入力とし、変更した単位を全て再計算する。双方向encoderを使う場合、未変更tokenの表現まで再利用してはいけない。最大長を超える入力は黙って切り捨てず、既存tokenizerの窓処理と位置整列を使う。窓境界の関係・重複位置の扱いは実装前に固定する。

教師側だけで語彙関係を覚える構成にしないため、最初に必要なのは教師量を増やすことではなく、参照から何の情報が届くかの確定である。

## 仮説を確かめる対照

| 仮説 | 固定する対照と観察 | 判断が変わる条件 |
| --- | --- | --- |
| H1a: 既知名詞でも未観測の結合へ、実在対象群から一般化できる | 対象を保って原動詞を変える対照と、原動詞を保って対象を変える対照。支持・名詞表現・適合をそれぞれ読む | 話題の近さだけで不適切な対象も支持するなら名詞表現を見直す。別動詞の実例で原動詞を支持していたら照合条件を直す |
| H1b: 文中の説明を使えば、名前の未知と対象意味の不明を分けられる | 同じ対象の説明を保って名前だけを変える対照。静的名詞ベクトルの最小案は説明を入力しないため、この仮説の達成は検証できない | 文脈情報を取り込む案へ進む際の独立した問い。最小案では表現の取得状態と未確認を残し、造語を正しく解釈できたとは主張しない |
| H2: 意味が理解できることを、慣用的な語の選択と取り違えない | 既知の名詞を用いた語彙誤用と正用。原語の支持と一般化適合が食い違う場合を事前に含める | 適合が高いだけで原語の不支持を打ち消すなら、その情報の統合を見直す。未観測だけで誤りにする修正もしない |
| H3: 参照不足を誤用根拠にしない | 同じ入力の参照情報だけを利用不能にする対照。ベクトル取得不能・条件未観測・原語ペアゼロ・キーの表現不能を区別。対象意味の正否が未確認な状態も明記 | 欠損そのものによる警告増加を確認したら、欠損処理・教師・資料の原因を分ける。保留増加だけを検出改善と呼ばない |
| H4: 集計や表現が、必要な使い方の違いを消していない | 同じ原語ペアで文脈が異なる対照と、上表の既知のキー衝突。入力と参照原文を対応させる | 参照側の区別が消えるなら索引・用例表現を直す。失われた情報を学習回数や閾値では補わない |

対照の正誤を今回のモデル出力で決めない。寺村の語彙span・公式カテゴリは既存goldだが、「意味は通る」「稀な正用」「別用法」の注釈はない。教師訂正文には未修正箇所もあり、完全正用goldにできない。少数対照では元資料の注釈と追加の読解判断を分け、LLMによる判断を人手goldへ混ぜない。

原例に必要な違いがないのにhash順で数文を選ぶだけでは、仮説を検証できない。学習前に検証する違いと入力を固定し、合致しない例を未確認として残す。少数対照は情報と機構の確認に限り、汎用性能の証拠には使わない。

## 工程と判断の順序

1. **設計と情報契約を確定する。現在はここにいる。** 目的を上の問いへ分け、既存研究・公開解析で何を取得できるか確認する。既知の情報欠落を学習後の検討へ先送りしない。未確認の前提に対応する調査だけを追加する。
2. **一つの構成を最小実装し、仮説を検証する。** 対照と期待する情報差を先に固定する。変えるのは検証対象の情報だけ。解析・参照・一般化・判定のどこで差が失われたかを追う。必要なら、その原因に対応する設計へ戻る。
3. **構成を固定して範囲を広げる。** 既存の学習者・同一全文を分離した資料で、語彙誤用、正用への警告、未知対象、未評価、原文位置を測る。単体scoreによる採否ではなく、目的との距離と残る原因を示す。AI技術文への性能は学習者文の数値で代用しない。
4. **実利用と品質を確認する。** スクリプト・textlintへ接続し、解析を含めた常駐時の遅延、起動、長文、Markdown・Unicode位置、メモリ・容量を測る。訂正候補は別評価。fresh contextで保守性・単純さ・テストの妥当性をレビューする。

計算量と保存量は工程1から見積もり、工程2で実測する。全tokenごとのmask反復や全用例のオンラインencoder処理を、速度の根拠なく導入しない。対照に通ったことと、一般入力で役立つことを別の完了条件にする。

## 研究の位置付け

- [Erkほか2010](https://aclanthology.org/J10-4007/)と[Chersoniほか2018](https://aclanthology.org/W18-4603/)は、実在の対象群から条件付き適合を一般化する根拠。日本語の自由文の誤用検出性能を示すものではない。
- [Inoueほか2016](https://aclanthology.org/C16-1266/)は、同じ対象の別の出来事・役割を使う選択選好を扱い、名前を伏せた対照も評価する。対象名と対象情報を分ける参考であり、英語の出来事のもっともらしさを日本語の慣用的正しさへ読み替えない。
- [Herbelot・Kochmar 2016](https://aclanthology.org/C16-1093/)は、代替語の優位だけによる過剰訂正と文脈・分布情報の役割を扱う。検出と候補の優劣を分ける根拠になる。
- [Bellほか2019](https://aclanthology.org/W19-4410/)と[Caoほか2020](https://aclanthology.org/2020.nlptea-1.7/)は、文脈表現の再利用や統計情報との融合の先例。少量教師が失われた参照側の情報を復元できるという根拠にはならない。
