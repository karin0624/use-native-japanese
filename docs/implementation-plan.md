# 目的、設計、検証の順序

目的は、AIが出した誤った日本語をリアルタイムで位置付き指摘し、可能なら訂正案を出すこと。技術文・一般文の語彙選択と不自然な組み合わせを重点にする。用例検索、構文解析、一般化は手段であり、個々の方式の実装完了を目的の達成としない。

## 現在の工程

工程3の[固定した最小検証](minimal-validation.md)を終えた。存在照合と位置保存は確認できたが、未観測候補は教師訂正側を含む4全文へ広がった。現在は**工程2の参照資料と警告判断の設計へ戻っている**。

現在の構成は[最小の用法照合](architecture.md)を正本とする。既存解析から原語・構造の比較条件を全列挙し、用例との一致／不一致と原文位置を返す。不一致を警告候補として観察する段階であり、検出性能の成立を宣言するものではない。

比較表現・費用の既存証拠、今回の全候補・元注釈対応は再利用する。次は、単語未収録と既知語間の未観測を誤用の根拠へ読み替えない構成を検討する。その際、参照範囲、比較条件、公開解析のどの不足に対応するかを示す。現資料を増やせば解決するとも、分類器や警告抑制が必要ともまだ決めない。新しい構成・残る仮説・終了条件が定まるまでは、実装・追試・全量処理を始めない。

## 工程と判断の順序

1. **課題と必要機能を定義する。** 入出力、目的、対象を明確にする。名詞が何を指すかと、名詞・動詞等の組み合わせが適切かを混同しない。手段や将来の拡張を要件へ昇格させない。
2. **実現方式と検証計画を決める。** 既存研究・保守中の実装・issue等から設計判断を行う。情報を保持できないことが設計上分かるなら、実験や追加モデルで埋めず設計を直す。残った仮説、必要な根拠、最小実装、結果に応じた判断、終了条件を固定する。
3. **残った仮説だけを最小実装で検証する。** 工程2で定めた範囲を実施し、支持・反証・未確認を区別する。既存の証拠を再利用し、同じ確認を繰り返さない。新たな問題を見つけても、その場で対策を実装せず、原因を確認して必要な設計箇所へ戻る。
4. **構成を固定して範囲を広げる。** 工程3の結果で進行可能と判断した構成を、独立した資料・入力へ広げる。拾える誤用、正用への警告、未評価、原文位置を確認する。資料拡大や全量処理は、この工程の目的と予算を決めてから行う。
5. **実利用と品質を確認する。** スクリプト・textlintへの接続、常駐時の遅延、長文、Unicode・Markdown位置、容量を検証する。必要な訂正案を別に評価し、fresh contextで単純さ・保守性・テストの妥当性を確認する。

工程3の完了は、固定した問いに対する証拠と不足原因を整理し、工程4へ進めるか、どの設計へ戻るかを判断できる状態である。少数対照の成功を汎用性能の証明にしない。「警告候補」と呼び換えることで、目的に役立つかの確認を省略しない。

## 工程3に残す問いと実行範囲

| 問い | 使う証拠・必要な最小作業 | 結果による判断と終了条件 |
| --- | --- | --- |
| 比較条件は、検出したい使い方の違いを保持するか | 原動詞・形容詞・関係を保持する。既存の「精度を高く／大きくする」「会社に／で勤める」の解析記録と、同じ出現の共同条件を確認する。独立arcの衝突が、現2〜4 nodeの比較で解消されるか未確認の箇所だけ調べる | 必要な違いがkeyで同一になるなら比較条件の設計へ戻る。設計通りの違いが実装で消えるなら実装を直す。各対照を「保持できた／設計不備／実装不一致／なお未確認」と記録し、変更不要か、戻る箇所はどこかを判断して終える。解析器の総当たりや独自の日本語修復規則は追加しない |
| 一致／不一致と位置が、どの警告候補になるか | 完成索引内の実出現との一致、原文offset、未観測結果を読む。既存の生出力を使い、不足する位置対応だけ最小限で確認する。誤用・正用の観察には、必要な対照を元資料の注釈とともに実行前に固定する。速度用に選んだ9入力だけを正誤評価の代用にしない | 参照にあるのに一致しないなら解析・key・索引のどこで異なるかを確認する。正用が未観測でも、先に頻度・類似度の抑制を入れない。確認できたことと未確認を分け、問題があれば資料範囲・比較条件・実装のどこに原因があるかを調べる。変更不要か、戻る箇所はどこかを判断して終える |
| 全候補照合の費用はどこにかかるか | 完了済みの12入力・1,000段落索引での存在照合計測を再利用する。解析・列挙・存在照合・初回loadを分ける。名詞一般化や周辺統計の費用を混ぜない | 現在の規模での処理時間と支配項は記録済み。別の規模・条件が必要になるまで再測定しない。全資料や任意長への速度保証は未確認のまま、範囲拡大時の判断へ引き継ぐ |

対照の正誤を、この検出器の出力やLLMの判断で正解化しない。寺村の原注釈、教師訂正文、利用者が挙げた問題例はそれぞれの来歴を保つ。教師訂正文は完全な正用goldではない。固定groupの保留testは、この工程の調整には使わない。

旧記録の「友人に話す／友人について話す」は、解析表現の性質を調べるために当方が追加した補助例で、利用者の誤用例ではない。話し相手と話題の違いはあるが、どちらも正しい表現である。両者の支持を分離できないことを誤用検出の失敗や必須の修正課題とせず、この区別を検出要件へ加えない。

新しい入力や作業が必要なら、上表のどの未確認事項を解消するか、必要な違いを含む入力は何か、何が分かれば終わるかを先に追記する。問いの範囲自体が変わる場合は、先に工程2へ戻る。

## 既存の結果と停止している作業

- **保存・検索の機構:** 完成1,000段落の索引で、保存形式の変更後も全件数・記事数・引用・候補が一致した。これは索引の検証であり、誤用検出性能ではない。
- **全候補の存在照合:** 固定12入力で打切りなく完走。16〜71字の9入力は0.031〜0.072秒、1,900字は2.073秒、初回loadは14.396秒だった。1周・1,000段落索引の結果であり、一般的な速度の保証ではない。名詞一般化等を含む別経路の54〜67秒を、この結果へ混ぜない。
- **未観測結果:** 速度用のdev9入力では1,163個の異なる候補中1,104個が未観測だった。参照由来3入力は全て一致した。この数値は誤用率・誤警告率ではなく、必要な正誤対照の代わりにはならない。結果の原因を確認する前に警告を抑える処理を追加しない。
- **全量解析:** 69,195文書の処理は23,670文書を保存した状態で安全に中断し、`complete=false`を維持した。原本と完成1,000件の資料は保持している。工程の見直し完了だけを理由に全量処理を再開しない。
- **範囲外の追加案:** 頻度・associationによる細分化、名詞一般化による保留、参照文脈prototype、9枠、HGB、これらを必須としたruntime接続は、現在の仮説検証に含めない。参照encoderの全量計算は未開始。成果・研究記録は保持するが、既に書いたことを採用理由にしない。
