# 目的、設計、検証の順序

目的は、AIが出した誤った日本語をリアルタイムで位置付き指摘し、可能なら訂正案を出すこと。「重複を畳む」のような用例に裏付けられない語の使い方が中心であり、正用同士の意味差を識別する問題へ広げない。用例検索、構文解析、一般化は手段である。

## 現在の工程

**[固定二入力の限定照合](lexical-usage-validation.md)を実施し、観測された入出力の接続不足について工程2へ戻る。** 「つけています／つける」はJuman++の正規化値、「を／も」の関係はKWJAのヲ格として、使用実績と原位置へ接続できた。一方、参照8件の空白による座標差と1件の本文コメント化があり、参照全体での未観測判定は未達である。次はこの二つの原因に対応する接続仕様を決める。

位置差8件は、標準difflibによる解析座標と原文座標の対応を工程3として実装する範囲を定めた。保存出力だけを読み、未対応が空白だけであることと全参加語の原文一致を確認する。本文コメント化の一件も、既存RegexSenterの分割規則を継承し、Sentenceの本文として構築する接続を選んだ。公開されたJumanppのsenter注入口から渡し、失敗した一件だけ再解析する。privateメソッド一点への依存と再解析の範囲は[限定照合](lexical-usage-validation.md#本文を保持する入力構築)に記す。両方を同じ対策で処理しない。

現在の判断は[目的と設計の見直し](design.md)を参照する。[構成の記録](architecture.md)は、既に検証した照合機構の説明であり、製品で採用する単位が確定したという意味ではない。

必要な情報は、既存解析による語の基本形、同じ出現の格関係、原文位置である。正規化はJuman++、主辞・格関係はKWJAの公開出力を使い、共通の形態素indexで接続する。正規化そのものを未解決の研究課題にしない。固定入力・取得済み資料・保存出力は維持する。原位置の対応は保存出力を再利用し、本文が失われた一件の再解析は入力構築の仕様を決めた後に限る。全文の指摘負担、警告分類、文脈モデル、頻度による抑制はこの工程へ加えない。全量処理や旧runtime接続は停止を維持する。

## 工程と判断の順序

1. **課題と必要機能を定義する。** 入出力、目的、対象を明確にする。名詞の新しさ・未収録と、その名詞へ述語をどう使うかを混同しない。手段や将来の拡張を要件へ昇格させない。
2. **実現方式と検証計画を決める。** 既存研究・保守中の実装・issue等から設計判断を行う。各情報・部品がどの要求を満たすか、どこまで主張できるかを確認する。情報を保持できないことが設計上分かるなら、実験や追加モデルで埋めず設計を直す。残った仮説、必要な根拠、最小実装、結果に応じた判断、終了条件を定める。
3. **残った仮説だけを最小実装で検証する。** 工程2で定めた範囲を実施し、支持・反証・未確認を区別する。既存の証拠を再利用する。問題を見つけても、その場で対策を実装せず、原因を確認して必要な設計箇所へ戻る。
4. **構成を固定して範囲を広げる。** 工程3の結果で進行可能と判断した構成を、独立した資料・入力へ広げる。拾える対象誤用、正用への警告、未評価、原文位置を確認する。資料拡大や全量処理は、この工程の目的と予算を決めてから行う。
5. **実利用と品質を確認する。** スクリプト・textlintへの接続、常駐時の遅延、長文、Unicode・Markdown位置、容量を検証する。訂正案を実装する場合は別に評価し、fresh contextで単純さ・保守性・テストの妥当性を確認する。

設計レビューは工程表への適合だけで終えず、利用者の元の要求へ遡る。実装レビューでは、その設計への適合を確認する。少数例の成功を汎用性能の証明にせず、低い単体scoreだけで方式を捨てない。「警告候補」と呼び換えることで、目的に役立つかの確認を省略しない。

対照の正誤を検出器の出力やLLMの判断で正解化しない。寺村の原注釈、教師訂正文、利用者が挙げた問題例はそれぞれの来歴を保つ。教師訂正文は完全な正用goldではない。固定groupの保留testは、この工程の調整には使わない。

## 再利用する結果と停止している作業

- **保存・検索:** 完成1,000段落の索引で、保存形式の変更後も全件数・記事数・引用・候補が一致した。固定4入力では341出現の照合・位置保存に接続不一致を認めなかった。対象用法の選び方や誤用検出性能の確認とは別である。
- **存在照合の費用:** 固定12入力で打切りなく完走。16〜71字の9入力は0.031〜0.072秒、1,900字は2.073秒、初回loadは14.396秒。1周・1,000段落索引の結果で、一般的な速度の保証ではない。別経路の名詞一般化等の54〜67秒を混ぜない。
- **未観測結果:** 固定4入力の全341出現中327出現が未観測で、そのnodeの位置は各全文を覆った。参照45記事では対象の二語関係も未収録だった。誤用率・誤警告率でも、一般分類器が必要という証拠でもない。数値と解釈の訂正は[検証記録](minimal-validation.md)にある。
- **全量解析:** 69,195文書の処理は23,670文書を保存した状態で安全に中断し、`complete=false`を維持した。原本と完成1,000件の資料は保持している。設計の見直し完了だけを理由に全量処理を再開しない。
- **未採用の追加案:** 頻度・association、名詞一般化、参照文脈prototype、9枠、HGB、それらを必須としたruntime接続。参照encoderの全量計算は未開始。研究・部品は保持するが、既に書いたことを採用理由にしない。
