# 語彙正規化と既成辞書の接続

全文検証で見つかった接続不備を直す工程である。必要なのは、元の語と同じ出現の格関係を、参照辞書が表す単位へ接続すること。「つける／つけています」を別の動詞にせず、接辞を主辞として拾っただけの「一体化→化」も避ける。述語句の意味を完全に保存する万能IDは要求しない。

## 調査から確定したこと

- `bp.pas`にはPAS以外の連想照応も入る。対象はcohesion-toolsの`PasExtractor.is_pas_target`と、固定したKWJAのPAS taskの格一覧から取得する。事態性名詞、判定詞、C/N/Oの区分は保存する。今回の修正で後三者を一括除外する判断はしていない。
- KNPは内容語・準内容語から基本句と文節の正規化代表表記を作る。格フレームの既存consumerは、項側に文節の主辞／主辞’代表表記を使う。アプリ側で接辞を連結する規則を作らず、この公開表記とその原文単位を読む。
- 複合語の表記は、辞書の`rep2id`で各構成表記をIDへ変え、`+`で連結して照合する。`?`は正規化表記の候補の区切りである。従来の単一ID lookupを複合表記全体へそのまま使うと、既存仕様と合わない。これは日本語の語を新たに切る処理ではなく、既存の表記形式から辞書IDへの変換として修正する。構成語のIDが欠けた候補を、残った語だけの用例支持へ変えない。
- 用言の正規化文字列をそのまま辞書keyにすることはできない。「正しくする」の正規化代表表記は「正しい」だが、参照keyには「正しい＋する」がある。格だけを残してもこの非対称な接続は直らない。
- KNPの公開指定`-no-use-cv-cf`は、既存の見出し生成で「畳んでいる→畳む」「正しくする→正しい＋する」「解決し始める→解決」を区別する経路を持つ。通常の用言代表表記はこの指定でも変わらず、実際の検索表記は格解析後の標準用言代表表記とcfidから取得する。
- 非CV経路も現在の辞書と同じbinary readerを使う。旧格フレーム向けとのコメントだけで形式非互換とは言えない。一方、現辞書への収録、実際の公開出力、確率DBの互換性は別に確認が必要である。
- 辞書の`ノ格~ガ`は、ガ格項を修飾するノ格であり、ガの別表記ではない。「架空の人物」は既存5recordの全欄にも人物IDがなく、欄の読み替えで解消する例ではなかった。

主な根拠は[KNPの見出し生成](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/case_ipal.c)、[格フレーム照合](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/case_match.c)、[PAS extractor](https://github.com/nobu-g/cohesion-tools/blob/v0.7.7/src/cohesion_tools/extractors/pas.py)、[KWJAの対象制限に関するissue](https://github.com/ku-nlp/kwja/issues/78)、[格フレーム公式仕様](https://www.gsk.or.jp/files/catalog/GSK2018-B/README.pdf)。ソース、論文、注釈基準、公開利用例、issueの調査記録は環境内の`pas-scope-research-20261022.md`、`lexical-unit-research-20261022.md`、`non-cv-key-research-20261022.md`、`caseframe-relation-research-20261022.md`にある。これらのfilenameは`/workspace/scratch/`からの相対名である。

## 残った仮説と最小検証

仮説は、**既存KNPの語彙正規化と非CV見出し生成を呼び出せば、独自の日本語規則を追加せず、観測した語の欠落を直して現辞書へ接続できる**ことである。格関係は保存済みKWJAの値を維持し、KNPが選んだframeの存在だけで原の使い方を支持とはしない。

入力は保存済みの「重複を畳んでいる」「情報を正しくする」「問題を解決し始める」の三文と、全文検証で「一体化」「中心的」「長さ」「機関車」の欠落を観測した原文の四文に固定する。同一文に複数の対象語があれば重複実行しない。既存形態素列と構造を再利用し、KWJAの再推論や新しい資料の取得は行わない。

KNPの公開入力形式で既存の文節・基本句境界と形態素情報を接続する。準備時のsource確認で、rhoknpのKNP再入力用変換ではJuman同形候補が`ALT`素性となり、native KNPが読む`@`行の候補を保持できないことが分かった。固定入力にも該当があるため、この変換を挟まない公開CLIへ標準のsubprocessでまとめて渡す。形態素行の出力と解析結果の読取りはrhoknpを使い、構文解析や同形候補の選択を自作しない。

既存の`-no-probcase`による非確率の格フレーム照合を使い、未取得の確率DBを暗黙に欠損させた既定解析とは区別する。この処理でKWJAの格を置き換えない。既存データを読み取り専用で参照し、別設定と出力をscratchへ保存する。実行は起動込み120秒を上限とする。

確認するのは次の対応である。

1. 全形態素の表層・順序・原文位置と、公開単位の対応が保持されるか。
2. 三対照の標準用言代表表記・cfidが、元の語に対応する参照keyを返すか。原用言表記と正規化表記も保存する。
3. 四つの欠落例で、語の前部を含む既存正規化を取得できるか。項側は既存consumerと同じ主辞／主辞’表記を使用し、辞書に当たる短い語を探索して選ぶ処理は作らない。
4. 得られたkeyが現辞書で取得できるか。項は既存の表記形式に従ってID列へ変換し、完全なID列を照合する。未収録、表記取得不能、用例未観測を区別し、結果に合わせた語別修正はしない。

成立した場合はこの接続を保存済み全文へ適用し、同じ入力で何が修正され何が残ったかを確認する。公開情報の不足や語の損失が残れば、その箇所の契約へ戻る。新しいparserの横並び試行、全複合述語の意味等価判定、頻度による警告抑制は追加しない。少数対照の成立を汎用性能の証明とせず、全文で残る未観測を原文・解析・参照へ戻して判断してから製品接続へ進む。
