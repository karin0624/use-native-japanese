# 語彙正規化と既成辞書の接続

全文検証で見つかった接続不備を直す工程である。必要なのは、元の語と同じ出現の格関係を、参照辞書が表す単位へ接続すること。「つける／つけています」を別の動詞にせず、接辞を主辞として拾っただけの「一体化→化」も避ける。述語句の意味を完全に保存する万能IDは要求しない。

## 調査から確定したこと

- `bp.pas`にはPAS以外の連想照応も入る。対象はcohesion-toolsの`PasExtractor.is_pas_target`と、固定したKWJAのPAS taskの格一覧から取得する。事態性名詞、判定詞、C/N/Oの区分は保存する。今回の修正で後三者を一括除外する判断はしていない。
- KNPは内容語・準内容語から基本句と文節の正規化代表表記を作る。格フレームの既存consumerは、項側に文節の主辞／主辞’代表表記を使う。アプリ側で接辞を連結する規則を作らず、この公開表記とその原文単位を読む。
- 複合語の表記は、辞書の`rep2id`で各構成表記をIDへ変え、`+`で連結して照合する。`?`は正規化表記の候補の区切りである。従来の単一ID lookupを複合表記全体へそのまま使うと、既存仕様と合わない。これは日本語の語を新たに切る処理ではなく、既存の表記形式から辞書IDへの変換として修正する。構成語のIDが欠けた候補を、残った語だけの用例支持へ変えない。
- 用言の正規化文字列をそのまま辞書keyにすることはできない。「正しくする」の正規化代表表記は「正しい」だが、参照keyには「正しい＋する」がある。格だけを残してもこの非対称な接続は直らない。
- KNPの公開指定`-no-use-cv-cf`は、既存の見出し生成で「畳んでいる→畳む」「正しくする→正しい＋する」「解決し始める→解決」を区別する経路を持つ。通常の用言代表表記はこの指定でも変わらず、実際の検索表記は格解析後の標準用言代表表記とcfidから取得する。
- 非CV経路も現在の辞書と同じbinary readerを使う。旧格フレーム向けとのコメントだけで形式非互換とは言えない。一方、現辞書への収録、実際の公開出力、確率DBの互換性は別に確認が必要である。
- 辞書の`ノ格~ガ`は、ガ格項を修飾するノ格であり、ガの別表記ではない。「架空の人物」は既存5recordの全欄にも人物IDがなく、欄の読み替えで解消する例ではなかった。

主な根拠は[KNPの見出し生成](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/case_ipal.c)、[格フレーム照合](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/case_match.c)、[PAS extractor](https://github.com/nobu-g/cohesion-tools/blob/v0.7.7/src/cohesion_tools/extractors/pas.py)、[KWJAの対象制限に関するissue](https://github.com/ku-nlp/kwja/issues/78)、[格フレーム公式仕様](https://www.gsk.or.jp/files/catalog/GSK2018-B/README.pdf)。ソース、論文、注釈基準、公開利用例、issueの調査記録は環境内の`pas-scope-research-20261022.md`、`lexical-unit-research-20261022.md`、`non-cv-key-research-20261022.md`、`caseframe-relation-research-20261022.md`にある。これらのfilenameは`/workspace/scratch/`からの相対名である。

## 残った仮説と最小検証

仮説は、**既存KNPの語彙正規化と非CV見出し生成を呼び出せば、独自の日本語規則を追加せず、観測した語の欠落を直して現辞書へ接続できる**ことである。格関係は保存済みKWJAの値を維持し、KNPが選んだframeの存在だけで原の使い方を支持とはしない。

入力は保存済みの「重複を畳んでいる」「情報を正しくする」「問題を解決し始める」の三文と、全文検証で「一体化」「中心的」「長さ」「機関車」の欠落を観測した原文の四文に固定する。同一文に複数の対象語があれば重複実行しない。既存形態素列と構造を再利用し、KWJAの再推論や新しい資料の取得は行わない。

KNPの公開入力形式で既存の文節・基本句境界と形態素情報を接続する。準備時のsource確認で、rhoknpのKNP再入力用変換ではJuman同形候補が`ALT`素性となり、native KNPが読む`@`行の候補を保持できないことが分かった。固定入力にも該当があるため、この変換を挟まない公開CLIへ標準のsubprocessでまとめて渡す。形態素行の出力と解析結果の読取りはrhoknpを使い、構文解析や同形候補の選択を自作しない。

既存の`-no-probcase`による非確率の格フレーム照合を使い、未取得の確率DBを暗黙に欠損させた既定解析とは区別する。構造付き入力では、`after_decide_dpnd`が格解析を呼ぶ条件に対応する公開指定`-case2`が必要である。この処理でKWJAの格を置き換えない。既存データを読み取り専用で参照し、別設定と出力をscratchへ保存する。実行は起動込み120秒を上限とする。

確認するのは次の対応である。

1. 全形態素の表層・順序・原文位置と、公開単位の対応が保持されるか。
2. 三対照の標準用言代表表記・cfidが、元の語に対応する参照keyを返すか。原用言表記と正規化表記も保存する。
3. 四つの欠落例で、語の前部を含む既存正規化を取得できるか。項側は既存consumerと同じ主辞／主辞’表記を使用し、辞書に当たる短い語を探索して選ぶ処理は作らない。
4. 得られたkeyが現辞書で取得できるか。項は既存の表記形式に従ってID列へ変換し、完全なID列を照合する。未収録、表記取得不能、用例未観測を区別し、結果に合わせた語別修正はしない。

成立した場合はこの接続を保存済み全文へ適用し、同じ入力で何が修正され何が残ったかを確認する。公開情報の不足や語の損失が残れば、その箇所の契約へ戻る。新しいparserの横並び試行、全複合述語の意味等価判定、頻度による警告抑制は追加しない。少数対照の成立を汎用性能の証明とせず、全文で残る未観測を原文・解析・参照へ戻して判断してから製品接続へ進む。

## 起動接続の訂正

最初の実行は設定引数を`-rcfile`とした実装誤りにより、KNPがUsageを出して終了した。解析出力・辞書照合とも0件であり、正規化の成否を測った実験ではない。公開指定は`-r`である。失敗記録を保持し、この引数と、sourceの分岐から確認した`-case2`指定を直して同じ固定入力を実行する。入力・比較条件は変更しない。

## 固定7文の結果と次の確認

訂正後のnative解析は7文158形態素を2.538秒で処理した。表層・順序・位置、文節と基本句の境界・係先は保持された。三対照では「畳む」「正しい＋する」「解決」の実在keyを得た。四つの欠落語も前部を含む既存正規化を取得でき、項側の複合ID変換も接続した。ただし「一体化」は正規化・主辞・通常の用言表記が`一体/いったい+化/か`なのに、標準用言表記は`化/か`となり、`CF_NOT_FOUND`も付いていた。標準用言表記だけを原語の参照keyとする仮説は、この例では成立しない。

元の語を表す公開情報は取得できている。次は保存済みの`一体/いったい+化/か`を現辞書へ完全一致で一度照会し、keyとrecordの有無・格欄を確認する。目的は、非CVの検索先の縮小と原語keyの未収録を分離すること。存在しても、この段階では原の使い方が支持されたとはしない。不在でも「化」の結果へ読み替えない。追加解析・追加資料・独自の語分割は不要である。

同じ公開表記を取得するためだけのCV再解析は加えない。語彙keyの保持、入力と辞書の格の互換、相手語の用例支持は別々に確認する。通常の用言表記には受動等も含まれるため、それを取得できたことだけからKWJAの意味格と辞書欄を無条件に同一視しない。次の診断結果と既存consumerの格の扱いから、保存済み全文へ適用する接続を確定する。

生出力、同形候補、辞書の不変性、rhoknp読取り時のS-ID行末空白だけの修正は、`/workspace/scratch/normalization-connection-20261022/report.md`に記録した。失敗時の出力も保持し、native解析は再実行していない。

## 接続条件の訂正

完全一致診断で`一体/いったい+化/か`の30recordを取得できた。原語keyの未収録ではなく、非CVの選択先だけが縮んでいた。既に得た通常の用言表記を捨て、選択された標準表記だけに依存する必要はない。

格の前提も訂正する。[公式注釈基準](https://nlp.ist.i.kyoto-u.ac.jp/nl-resource/corpus/KWDLC-1.0/doc/rel_guideline.pdf) §3.7.1では受身等も出現形に対して格を付ける。KWJAの格を能動原述語へ統一済みの役割と扱わない。CV辞書も出現形ごとに構築され、通常用言表記の直接検索時は既存consumerが格を変換しない。能動baseへの移動には別の対応が必要で、非CVの公開cfidだけからその対応を復元することはできない。

次の全文再検証では、同じ出現の通常用言表記をF、基本句の正規化代表表記をC、非CV標準表記をNとして、以下の接続を使う。

- Fは同出現形の辞書keyとして、入力PASと同名の直接格欄へ照会する。公開表記形式の複数候補は出自を保つ。
- N=Cかつ同じKNP基本句の完全な公開featureに`態`がない場合は、Nも照会候補にする。`set_pred_voice`はこの場合にvoice=0となるため、格交替の逆変換を作らず接続できる。N=Fは同じ照会なので重複させない。Fがない名詞述語でも、この条件を満たすNは同様に扱う。
- 原の語と異なるNは、その語の支持へ転用しない。「一体化→化」はこの条件を満たさず、Fの原語keyを使う。「畳んでいる→畳む」「解決し始める→解決」はN側で語彙的な結び付きを照会できる。
- 用言の種類は、既存consumerと同じ`用言`／`非用言格解析`の公開値でrecordの種類に対応させる。別種のrecordだけに相手語がある場合を支持としない。
- 候補ごとにkey未収録、用例未観測、読取り未完了、支持を保持する。Nの支持を述語句全体の支持とは呼ばない。条件を満たさない出現も原文・全公開値と未接続理由を保存し、製品で対象外にする判断とは分ける。

これは辞書照会への接続条件であり、独自の形態素連結、語尾削除、態から格への対応表ではない。根拠は[格の初期化](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/case_data.c#L774)、[辞書の型照合と格交替](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/case_ipal.c#L1595)、[格交替を扱う研究](https://www.jstage.jst.go.jp/article/jnlp/21/6/21_1207/_pdf/-char/ja)。調査記録は`/workspace/scratch/case-schema-connection-20261022.md`にある。

まずreaderの種類照合を小さい形式fixtureで検証し、保存済み7文を再解析せず再照合する。接続に不一致がなければ、同じ条件で保存済み22本文へ戻す。KWJAの再推論や新しい資料は不要で、既存形態素列・分割・依存構造をKNPへ一度渡して公開正規化を取得する。処理上限は起動込み120秒、原文位置と境界の対応を全件検査する。旧関係との対応・支持の根拠・未接続の実例を残し、前回と同じ20監査対象と新たに判明した接続不能を原因別に確認する。語別修正や頻度による警告抑制は加えない。
