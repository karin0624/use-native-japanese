# 同じ述語の実名詞から支持を広げる確認

目的は、直接の用例がない通常の使い方と、指摘したい語彙選択を区別する根拠を得ること。格フレームの採録には選別があり、「架空の人物」「ネックレスを持つ」も未観測だった。解析された語・関係の不一致は[別の確認](parser-connection-check.md)で扱い、類似度で補修しない。

## 加える情報

原述語・述語型・格を固定し、その欄で実際に観測された名詞との最大cosineを求める。直接支持は保持し、名詞の近傍支持を実語の用例とは呼ばない。類義動詞の用例、用例の頻度による重み、新しい分類器、補助コーパスはこの確認へ追加しない。

[Erkほか2010](https://aclanthology.org/J10-4007/)の用例と類似度による選択選好は実現原理の先例である。今回は最大値を使い、少数用法を多数派の平均で消さない。元論文の加重平均式の再現ではなく、ハブ語や話題の近さによる過剰支持も残る。実在する支持名詞を確認して、その原因を分析する。

既存のfastText圧縮配布とGensimの公開APIを使う。語彙外の名詞にも部分文字列から表現を得られること、モデルが約22MBであることが選択理由だが、語彙外でも意味を捉えられる保証はない。固定SHA-256、依存版、有限・非ゼロの確認は既存の読込み経路を再利用する。現在の複合代表表記とMeCab由来モデルの単位は一致しないため、その取得契約も確認する。

## 表記と用例の取得契約

- 保存照会の全対象recordから実語tokenを取得し、同じ述語・型・格を維持する。一般化属性・flagを実名詞へ変換せず、頻度を合算しない。
- `mrph2id.db`を既存pure-cdbの`iteritems()`で一度だけ順次読み、必要IDの全代表表記を逆引きする。逆引き用の全量DBは作らない。同じIDの別表記も保持する。
- 数字IDと`+`連結は構成順を保つ。用例側`?`の範囲は生成資料で未確定のため、原tokenを未接続として保存し、独立した観測名詞へ展開しない。未知形式・欠損成分も保存する。
- 単純な`見出し/読み`の各構成表記から見出しを読み、入力と用例に同じ処理を使う。区切りが一つでない等の未確認形式は推測しない。「長い＋さ」を「長いさ」と連結したり、「長さ」へ独自変形したりしない。
- 複合は全構成語のベクトルを既存APIで取得し、各成分を正規化して等重み平均、平均を再正規化する。一成分でも取得不能ならその候補の全体を不能とする。表記候補を一つの平均へ混ぜず、各候補の由来を保つ。これは汎用の加法合成であり、日本語の語尾や構文の生成規則ではない。語順を失い、派生語を十分に表せない可能性を記録する。

Gensimの平均は既定で欠損語を除くため、全成分の有限・非ゼロ確認を先に行う。参照候補の一部が不能なら、得られた最大値が比較可能な集合内の値であることを明記する。候補不能を低類似度へ変えない。詳細は`/workspace/scratch/nominal-vector-contract-20261022.md`にある。

## 保存例での一度の確認

最初は、新しい全文解析を加えず、正規化後22本文の次の9関係を使う。対象語と関係の対応を原文で確認済みの範囲である。

| 保存ID・関係index | 確認する使い方 |
| --- | --- |
| user:duplicate-fold / 0 | 重複を畳む |
| E1 / 1、E1:correction / 1 | ネックレスを着る／つける |
| teacher:723 / 0、teacher:723:correction / 0 | 電気をしめる／消す |
| C1 / 1 | ネックレスを持つ |
| 旧監査0、9、12 | 架空の人物、登場した機関車、中心的な勢力 |

F/N等の採用候補と由来は保存照会どおりにする。直接支持がある関係では近傍計算を省略できる。保存recordのaddressとhashを照合し、新しい述語keyを探索しない。全候補の処理件数、復号・取得不能、最大値と上位の実名詞・原token・frame、時間とRSSを保存する。代表表記や単位の不備を発見した場合は原因を記録し、結果に合わせた語別修正はしない。

scratchへ最小実装を置き、fresh contextで取得契約とテストの妥当性を確認してから実行する。全体5分を上限に一周し、途中結果を段階ごとに保存する。新しいモデル・コーパス取得、名詞以外の一般化、閾値探索は行わない。

## 判断と次工程

通常使用へ近い実名詞があり対象誤用は低支持に残るなら、事前固定した人手訂正9対と全文へ確認を広げる。人手訂正9対の来歴・選択条件は`/workspace/scratch/lexical-validation-inputs-20261022/selection.md`にあり、解析・照会結果で選んでいない。少数例から実用閾値や汎用性能を確定しない。

通常使用の支持元が辞書にない場合と、元名詞があるのに表現が近さを捉えない場合、対象誤用を過剰に支持する場合を分ける。前者なら補助用例の必要情報へ、後二者なら名詞表現・比較原理へ戻る。単体scoreが低いだけで用例方式を捨てない。復号や解析が未成立なら、採点の成否へ混ぜない。得られた一つの分岐を根拠付きで判断したらこの確認を終える。
