# 解析と正規化を同じ出力から取得する確認

現在の工程は、全文監査で観測した入力契約の不足に対応する設計の確認である。[同じ22本文の結果](coverage-validation.md#正規化接続後の同じ22本文)では、別基本句になった「抹消」を述語「済み」の公開表記から取得できず、名称に読み注記を混ぜた表記も残った。加えて、KWJAの省略項推定が本文の修飾先と異なる語を結ぶ例があった。これらを名詞の類似度で補修しない。

## 必要な機能と選択理由

必要なのは、原文の語彙単位、同じ出現同士の結び付き、原文位置の取得である。文脈中の省略項を全件埋めることは要件ではない。Juman++の形態素列からKNP自身に構造・格・正規化を決めさせれば、別解析器の基本句境界を正規化器へ固定する接続を減らせる。既成辞書と位置対応は再利用する。

これはKNPなら各反例が直るという結論ではない。既存sourceの`read_data.c`と`dpnd_analysis.c`は、現在の構造付き入力では係り受けを固定する。標準の`-case`は構造・格解析を行い、文脈の省略解析は別指定`-anaphora`である。保存native出力には明示格と連体の項があるため、必要機能を同一出力から得る根拠がある。詳細は`/workspace/scratch/single-parser-contract-review-20261022.md`にある。

KNPは辞書で関係を選択するため、辞書に乏しい用法の項を落とす可能性もある。選択frameの存在を用例支持には使わず、元の語と結び付きが得られたかを先に確認する。`CF_NOT_FOUND`、未割当、格取得不能は保存する。表層助詞や依存からアプリ側で格を補完しない。

## 一度だけ行う確認

保存済みJuman++の形態素入力を再利用する。KWJAの基本句・文節境界と係先を渡さず、原文の文字・形態素出現・同形候補を維持する。新たな形態素解析、KWJA推論、コーパス取得、辞書への追加照会は行わない。

対象は次の既存9文に固定する。同じ文に複数の対象があっても一度だけ渡す。

- 固定対照の「重複を畳んでいる」「情報を正しくする」「問題を解決し始める」の3文。
- 全文監査の「抹消済み」「パリクティン山とその読み」「デザイナーベビーと空括弧」の3文。
- C1の「黄色い上着」を含む全文。
- 固定監査の「一体化」を含む文。
- 保存native対照の「ファイルが削除された」を含む文。

同じruntimeと辞書を使い、公開指定`-case -no-probcase -no-use-cv-cf -tab -para-scode none`、既存の`-r`設定で一括実行する。確率DBは現在未取得であり、`-no-probcase`はCKYも無効にするため、以前の既定解析の性能を引き継いだとはしない。起動込み120秒を上限に一周し、失敗時は完成分と原ログを保存して止める。設定を変えながら反復しない。

全形態素の表層・順序・元位置と同形候補の入力保持を確認する。基本句の境界や係先は今回の解析結果なので、KWJAとの同一を合格条件にしない。各対象の原語、公開単位と由来、形態素範囲、相手語、格、F/C/N、cfidと未割当を比較表へ保存する。原の結び付きと比べて判定し、項が消えて指摘が減ることを改善と数えない。

## 結果からの判断

同じ出力で対象語と関係を保ち、観測した接合上の不備を減らせれば、解析責務を一本にする構成へ進める。これは参照辞書の不足や誤用判定を解決する変更ではなく、後続の独立全文検証も必要である。

必要な語や関係が失われる場合は、公開出力の具体的な不足を記録して採否を判断する。語別の例外・括弧除去・助詞対応表を追加せず、別解析器を順番に試す工程へも移らない。全ての自然言語解析の誤りを解消することを終了条件にはしない。

## 結果と次の評価での採用

9文176形態素の一周は起動込み6.256秒、native処理4.812秒、子process最大RSS約144MiBで完了した。全形態素の表層・順序・元位置と入力の同形候補を保持し、辞書と保存入力も不変だった。公開PASは45関係で、格・項・原文位置の取得に読取警告はなかった。この時間は保存形態素を入力した値であり、形態素解析を含む実利用の遅延ではない。

「重複を畳んでいる」「情報を正しくする」「問題を解決し始める」の元語とヲ格を保持した。C1の「黄色い」は「上着」へ対応し、「持つ」「着る」「つける」の明示対象も得られた。旧構造付きKNP自体も「上着」を返していたため、境界の変更がこの改善を生んだとは解釈しない。従来は別の解析器のPASを採用していたことが差の理由である。

「抹消済み」は別単位のまま、パリクティン山は名称の公開表記が得られても項が読み注記を指した。デザイナーベビーは名称全体への項がなく、「一体化」のFは全体を保つ一方、Nと選択frameは短縮した。これらは未解決であり、項が消えた例を誤警告の改善へ数えない。受動の「ファイルが削除された」では公開ガ格を保ち、能動ヲ格への変換は行わない。

**次の評価にはJuman++からKNPへの単一経路を採用する。** 必要な公開情報を同じ出力から得られ、KWJAの推論・境界との接合・文脈からの省略項推定を省けることが理由である。全ての名称や複合述語が改善することを採用条件にはしない。残る解析誤りと未取得は、後続の対照・全文評価で影響を記録する。これだけで製品の検出能力や速度を認定しない。

原記録は`/workspace/scratch/single-parser-check-20261022/`の`report.md`、`comparison.json`、`results.json`、`integrity.json`にある。manifest SHA-256は`c3c1084928df67a8a23805ae371ae8566bdb4dc54eb8b05d04264b542c8921d8`。原報告の「全対象を保持できなかった」は不足の記録として採用し、全件保持を要求する新たな進行条件にはしない。

## 通常文の遅延に対応する確認

[一般文での一周](full-text-support-check.md#一周で判明した二つの前提不足)は、最初の87形態素文でnative内部180秒timeoutに達した。固定sourceの`main.c`と`dpnd_analysis.c`では、`-no-probcase`がCKYを無効にし、各完成構造に格解析を繰り返す。現在の経路へbeamだけを付けてもその探索は制限できない。

必要なのは、普通の長さの入力から同じ出現の構造・格・正規化を取得することであり、格フレームへの適合を全構造候補へ反復すること自体ではない。**同じKNPの標準`-dpnd`で構造を決定し、その公開出力を`-case2 -no-probcase -no-use-cv-cf`へ渡す**構成を確認する。構造と格を別の解析器から混ぜず、独自の境界・日本語規則も加えない。

`-dpnd`の日本語CKYは規則・距離等の既存`calc_score`を使い、格フレームや確率格DBを呼ばない。必要な既存資源は取得済みである。`-case2`は与えられた一構造で格解析する公開経路で、以前の正規化接続でも使用した。構造選択に格情報を戻さなくなるため、解析値や精度の同一は保証しない。確率格解析をCKYへ混ぜる設定、追加DB、根拠のないbeam値は今回採らない。標準`-dpnd`の候補保持も一律の固定幅ではなく、実時間は残る仮説として測る。

確認は失敗した同じ一文と、保存済みの「重複を畳んでいる」「情報を正しくする」「問題を解決し始める」の三対照に限る。既存Juman++出力を再利用し、KNPの二段階を一度通す。原形態素・同形候補・原位置、構造の受渡し、F/C/N・型・格・元項を保存する。第一段の構造を第二段が保持したかを確認し、旧方式との構造一致を条件にしない。

scratchのGPT-6.1-sol実装をfresh contextでレビュー後、起動込み120秒以内で確認する。段階別の時間・RSS・失敗を残し、遅延を未解析や指摘なしへ変えない。計算の膨張が解消し対象の原語と格が保たれれば、この二段階を全文確認へ採用する。不十分なら実際に残った原因へ戻り、候補数・文長の切捨てや語別補修を加えない。
