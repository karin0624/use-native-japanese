# 文節の機能表現を除くv10の検証

2026-10-27、Issue #15。公式GiNZA 5.3.0と軽量ja_ginza 5.3.0、spaCy 3.8.16、SudachiPy 0.6.11、SudachiDict-core 20260723で、`ginza-bunsetu-functional-projection-v10`を検証した。名詞群平均と境界0.35は固定し、本再構築で新しい用例・資料・評価入力・語別規則・閾値調整は加えていない。[設計](design.md)の比較条件を入力と参照へ対称に適用した。

## 変更の根拠と限定確認

主辞句APIの選択集合を語全体とみなしたこと、名前を分割した解析結果へ後から全名を投影したこと、文節の`CONT`を独立した語彙分類とみなしたことが、接続設計の前提不備だった。必要な比較条件から設計を見直し、所属文節の非機能側の語彙を保持し、解析前に名前の境界を決め、公開依存関係`aux/case/cop`も機能側として読む方式へ修正した。機能表現は公開`Token.children`で取得できるため当方forkを撤去し、公式GiNZAへ戻した。元の品詞・依存辺を想定どおりに書き換える修正ではない。

語彙取得の限定確認では「同一視」の両成分と「対応付ける」の両成分を保持した。ASCIIの[UAX #29 WB5/8/9/10](https://www.unicode.org/reports/tr29/tr29-49.html#Word_Boundary_Rules)に基づく連続英数字と、従来の英字/_開始の記号を含むprofileを分離した確認では、既存2本文のhash5個が全名一tokenとなり、部分名への端点は0だった。通常ASCII・整数/小数・日付/算術の3対照は新規結合0で、既存の一token lemmaを保持した。名前全般や列挙の外側構造を完全に扱える証拠ではない。

機能側の限定確認は保存6Doc・10anchorへ無推論で適用し、case2個とaux2個だけを追加除外した。同一視・対応付ける等の対照に新たな語彙損失はなかった。`fixed`は[UD Japanese](https://universaldependencies.org/ja/dep/fixed.html)と[UD universal](https://universaldependencies.org/u/dep/fixed.html)の複合機能表現として直接子だけを読む。`mark/cc`は追加していない。この限定確認ではcopの追加除外や新規fixed除外の陽性例はなく、全用法の完全な語彙IDを保証しない。

## 追加の作用と残る限界

核心43本文396関係の全遷移は、`review→review`276、`indexed→indexed`30、`supported→supported`87、`review→indexed`2、`review→supported`1。逆方向の状態変化はなく、指摘は558→552。既知5本文12関係は`review`9、`supported`3、指摘18で不変だった。未注釈位置への指摘件数は負担の記録であり、誤指摘率ではない。

16820#1の「世界的／大ヒット」は、原語・ADJ/acl/head・文字位置[178,181)と[182,186)を保ち、Dの別記事3066353#0から直接支持を得て両端2指摘が消えた。既知2969604#0も同様だった。所定情報の追加による限定的改善であり、既知に効果を観測した分割を用いた盲検ではない対照である。同全文の別関係も平均0.327050→0.353364で支持へ移ったが、全文を完全正用goldとはせず独立の正答改善に数えない。

Python135テストと19 subtests、Node24テスト、Ruffは通過し、fresh contextのv10レビュー指摘は0件だった。これらは回帰と接続の証拠であり、日本語全般の正答を示さない。
