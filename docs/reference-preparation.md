# 参照資料を広げるための準備

目的は、未知の文章を照合できる参照資料を、現実的な時間と容量で用意すること。二入力の接続確認を汎用性能の根拠にせず、取得済み全文の全量解析も先行させない。

## 今決めること

**KNPの公開配布辞書にある既成索引を直接読む経路を検証する。** 必要なのは原述語・格・相手語の観測情報であり、原文引用や全文の再解析を必須にはしない。既存のCDB readerと辞書形式の接続を使い、別DBへの全量変換を避ける。下記の一括解析計測は終了し、追加のbatch調整は行わない。

現時点では[京都大学格フレーム](https://nlp.ist.i.kyoto-u.ac.jp/index.php?京都大学格フレーム)の大規模集約と、[NLT/TWC](https://tsukubawebcorpus.jp/)の大規模用例検索が存在する。一方、GSKの申請制資料、Web検索画面、実際に自動利用できる配布物を同一視しない。既存の研究記録を再利用し、KNP配布辞書との関係など取得経路を変える不足だけを追加調査する。

## 既存辞書への接続

[KNPの公式手順](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/README.md)は別配布辞書の公開ZIPを案内する。GSKの申請をその取得条件とする記載はない。公式source、issue・PR、外部利用例を確認し、高水準の専用readerは確認できなかったが、必要なCDB読取りには保守中の[pure-cdb](https://github.com/bbayles/python-pure-cdb)を利用できる。形式の根拠は同revisionの`system/ipal.c`と`system/case_ipal.c`である。

残る仮説は「既成辞書の原語・格を、保存済み入力の正規形へ接続でき、必要なframeだけの読取りで済む」である。まず固定二入力の正規形を使い、実ファイルの形式と照合結果を確認する。新しい日本語解析や独自の構文規則は実装しない。

- `cf.db`の完全一致keyに登録された全addressを既存readerで列挙し、`cf.dat`の該当recordだけを読む。`mrph2id.db`で相手語の代表表記をIDへ対応させる。曖昧表記の分割、複合述語の縮約、別の述語への置換は行わない。
- 格欄の末尾「格」等の公開ファイル形式を接続する。表層助詞から格を推測する規則は書かない。一般化属性を実語の出現へ数えず、頻度をframe間で合算しない。
- 辞書のhash、frame IDとaddress、入力の正規形・格、対応する原値を保持する。原語の支持、未観測、key未収録、形式未対応を区別し、資料の不足を誤用確定へ読み替えない。これは読取りの状態であり、新しい警告分類や採点方法ではない。
- 現物が公開形式と異なる場合は接続仕様を再確認する。実ファイルの読取りと保存済み入力の照合が成立すれば、この形式検証を終え、独立入力へ広げる。二入力の結果だけで検出性能を主張しない。

取得は既存のfsspec HTTP range fileと標準`zipfile`を使い、次の三memberだけを逐次展開する。

| member | 展開bytes |
| --- | ---: |
| `dict-bin/ebcf/cf.db` | 20,433,641 |
| `dict-bin/ebcf/mrph2id.db` | 232,591,272 |
| `dict-bin/ebcf/cf.dat` | 4,332,949,641 |

圧縮部分の合計は約1.667GB、最終容量は4,585,974,554 bytes。全ZIP・複製DB・ディスクcacheを作らない。開始時に残り展開量と512MiBの空きを確認し、HTTP range、配布物の更新条件、中央directoryの既知サイズ、CRC、展開サイズ、hashを検査する。完成ファイルは再利用し、不完全な取得を完成扱いにしない。取得の経過上限は15分とし、失敗時に全ZIP取得や別資源へ自動で切り替えない。実装とデータはscratchへ置き、fresh contextレビュー後に取得する。

既存HEADのLast-Modifiedは2017-05-02であり、取得時にも確認する。これは生成AI普及前の配布物を示す資料で、各原文の正確な収集・公開日ではない。辞書の個別許諾とWeb／GSK版との対応は未確認で、コードのBSD許諾やGSKの会員条件を転用しない。辞書自体をGitへ含めず、今回の接続検証から再配布の許諾を推定しない。

調査原記録は`/workspace/scratch/caseframe-reuse-20261022/`の`report.md`と`local-loader-design.md`にある。

## 公式一括入力の限定計測

仮説は、同じwordモデルに複数文書を一括で渡すことで、文書ごとの準備処理を繰り返す費用を減らせることである。用例の判定方法や日本語解析の独自実装を増やす実験ではない。

[KWJA 2.5.1のREADME](https://github.com/ku-nlp/kwja/blob/v2.5.1/README.md)、[CLIと公開テスト](https://github.com/ku-nlp/kwja/blob/v2.5.1/tests/cli/test_cli.py)には複数ファイル入力とbatch指定がある。実装は複数DocumentをJuman形式の中間ファイルへまとめ、同じword処理へ渡す。[上流PR 260](https://github.com/ku-nlp/kwja/pull/260)にはword推論の大きな中間配列についての報告があるが、修正先はdevであり、今回のstableへ取り込まれたとは扱わない。公開機能の存在は、CPUでの高速化や結果同一の保証ではない。

- 固定33文書の保存済みJuman++出力を使う。本文欠落を直した一件は追加出力を指定する。Juman++は再実行しない。文書境界を保ち、複数文書を一文書へ連結しない。保存値にはS-IDがなく、元IDの `#` はrhoknpのS-ID形式で受け付けられないため、公式 `add_doc_ids` / `add_sent_ids` で一意な転送IDを付け、元IDとの一対一対応を保存する。本文の文字置換は行わず、出力IDの重複・欠落・未対応を検査する。
- 同じKWJA 2.5.1、word tiny、CPU、4 threads、既存cache、offline設定を使う。公式CLIの一括ファイル入力を一度実行し、`--word-batch-size 4` とする。これは一括処理の成立を測る固定値で、最適値探索はしない。
- 起動込み180秒、親子processのRSS最大観測値10GiBを上限とする。現在の16GiB環境内で計測を終えるための作業予算であり、製品の必要メモリではない。新モデル・依存の取得、上流コードの書換えは行わない。
- 全33文書のID・本文・文／形態素index・位置を照合し、保存済みの主辞・格・関係の両端と比較キーを比較する。相違は隠さず記録する。実装の都合で異なる出力を同じと扱う正規化規則は足さない。
- 起動を含むCLI総時間、保存出力の読取り時間、RSS、文書／文字／形態素数を残す。測れない起動と推論の内訳は推定で分離しない。Juman++を再実行しないため、その時間を含む参照構築全体のスループットとは呼ばない。

実装はscratchに限り、既存の読取り・位置対応を再利用する。fresh contextレビュー後に実行し、出力は別に保存する。全33文書の接続が保持され、時間と容量が分かれば、この計測を終了する。差があれば公開処理のどの段階で生じたかを確認し、別モデルの試行へ広げない。計測だけで未知入力の検出精度や全量処理の採用を決めない。

### 計測結果

一回の公式一括実行は180秒上限で停止し、完成出力は返らなかった。最大観測RSSは3.44GiB。33文書・63内部exampleの読込みまでは記録されたが、推論とwriterの時間内訳は分からず、保存出力との同一性比較も未実施である。元の33件の解析・位置対応は不変。これを一括処理一般の失敗や全量解析時間の根拠へ外挿しない。追加計測は行わず、参照準備は既成辞書の接続へ進める。原記録は`/workspace/scratch/kwja-batch-measure-20261022/report.md`。
