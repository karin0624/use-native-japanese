# 目的と採用判断

## 作るもの

日本語の技術文書や一般文から、不自然な語の組み合わせ・語彙選択を検出し、修正候補となる箇所を位置付きで返すlint。AIによる文書生成の後にスクリプトから呼び出し、生成元へ指摘を返す。高速な反復実行と、将来の商用利用を考慮する。

作者の判定、分野に応じた文体の強制、自動書き換えは対象にしない。新しい用語や未見の表現を、珍しいという理由だけで誤り扱いしない。

## 目的と手段の区別

用例から正しい使い方を集めること、名詞ベクトルで未見表現を一般化すること、名詞・格・述語を索引化することは実現案だった。これらを製品の要件に固定しない。文全体を受け取って誤り箇所を返す既存モデルで目的を満たせるなら、独立した構文抽出器も用例索引も不要である。

初期実装のextractor.pyは独自の日本語構文規則を含むため採用しない。また、最大類似度やCSLSから警告を決める初期の採点方式も、連語誤用検出への有効性を検証できていない。解析器だけ交換して完成したとは扱わない。

形態素解析・係り受け・述語の解釈が必要な方式では既存ツールを利用する。解析器が扱えない構文を例文ごとの条件分岐で補完しない。内部表現が目的に対して過剰な条件を要求している場合は、表現や方式を見直す。

## 比較する既存方式

先行研究と公開成果物は[調査記録](prior-research.md)に整理する。公開モデルを製品コードと分けて実測したが、まだ製品には採用していない。

| 候補 | 既存APIで確認できたこと | 残る制約と判断 |
| --- | --- | --- |
| 日本語GECToRの誤り検出ヘッド | 元TensorFlow版の公開predict()からtokenごとの正誤出力を取得 | 第三者ONNXは現行Runtimeで読込失敗。元版は旧依存を必要とし、少数例での検出不足と遅さが残った |
| 日本語ELECTRAの置換語検出ヘッド | 配布checkpointの学習済ヘッドを確認し、標準AutoModelForPreTrainingで局所スコアを取得 | 少数の語彙選択対で想定した分離が得られず、日本語誤用検出スコアとして未実証。tokenizer依存も現行Transformers主版に未対応 |
| 日本語ModernBERT＋Oddballness | 公式MLMとfast tokenizerで原文位置付きスコアを取得 | tokenが助詞・述語をまたぎ、自然な対照や専門用語にも高い値。局所指摘の精度と速度に課題 |
| Tohoku BERT v3＋Oddballness | 公式形態素tokenizer、既存alignment、公式Optimum/ONNX Runtime APIで実行。追加学習なし | 少数例の接続確認を経て、固定したdev/test各300誤正対による限定比較を実行中 |

置換語スコアやMLMの外れ度を、そのまま現実の誤用確率とは呼ばない。訂正性能や全種類を含むGEDの成績も、連語・語彙選択だけの検出性能には読み替えない。現在の限定比較でも、教師作成の擬似誤用と実学習者の誤用を区別する。

候補が要件を満たさない場合は、既存手法による学習やデータ整備を含めて検討する。誤字だけの検出へ対象を狭めたり、試験用の数例への一致を完成基準にしたりしない。

## 検証と接続

公開モデルの実行可否と、必要な違いを区別できるかは別々に確認する。少数の対比例は設計を反証するために使い、汎用性能の根拠とはしない。実文書の検査では、取得元・版・選択方法を固定し、閾値調整に使うdevと最終評価のtestを分ける。検出位置、見逃し、誤警告を確認し、モデルの公表値を対象の異なる文書へ転用しない。

Tohokuのslow tokenizerには原文offsetがないため、spacy-alignmentsの公開APIでtoken列と原文文字を対応付ける。特殊token・未知語・不明な対応を推測で復元しない。語や構文ごとの独自ルールは追加しない。

初回ロード、起動済みの処理、反復時の時間とメモリを分けて測る。既存の速度値は共有CPU環境と少数入力での観測であり、一般的な処理性能を保証しない。コードのライセンスと学習済重み・データの利用条件も分けて確認する。

採用後に診断の位置・スコア・メッセージをCLIのJSONとtextlintへ接続する。モデルを保持するワーカーやMarkdownの位置写像は再利用できるが、名詞・格・述語を全方式共通の必須データ形式にはしない。

実装後は独立したcontextのsubagentが、既存ライブラリの再利用、不要な独自処理、テストの妥当性、保守性をレビューする。モデル、コーパス、認証情報はGitに含めない。
