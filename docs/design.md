# 目的と現在の判断

現在は方式選定の調査段階であり、製品方式は未採用である。参考意見を採用決定として扱わない。検索器、コーパス統計、BERTのいずれにも方針を固定していない。

## 目的と手段

AIが出した誤った日本語をリアルタイムで位置付き指摘し、可能なら訂正案を出す。技術文書・一般文を自由文のまま受け取り、不自然な語の組み合わせ・語彙選択を重点に扱う。スクリプトから自動で呼び出せ、textlintにも接続できることと、高速な反復実行を必須条件とする。将来の商用利用も考慮する。作者の判定、文体の強制、自動書き換えは対象外である。

参照会話の名詞・格・述語の三つ組、名詞側だけの一般化、コーパス、単語ベクトルは実現方法の仮説である。検索やBERTも含め、内部形式や特定の方式を要件にしない。必要な解析は既存ツールに委ね、独自の日本語構文規則や例文別の条件分岐を作らない。

## 比較している課題と証拠

| 候補 | 入力と出力 | 得られた証拠・未確認事項 |
| --- | --- | --- |
| 専用の教師あり日本語GED | 全文から誤りtoken・範囲を検出 | 日本語の直接先例がある。ただし総合GEDの成績では語彙選択の性能を示せず、対象カテゴリでの評価・配布重み・再現環境・速度を確認する必要がある |
| コーパス統計による全文検出 | 全文から候補箇所を抽出し、頻度や共起などで判定 | Chantokunなど日本語の直接先例がある。語彙別性能と、候補生成から判定まで再利用できる現行実装は未確認 |
| zero-shotモデル採点 | 全文の各tokenをMLM外れ度や置換語スコアで採点 | 公開日本語モデルを実測した。Tohoku＋Oddballnessの固定評価は完了したが、この構成をそのまま製品化する根拠は得られなかった |
| 用例検索・選択選好という部品 | 指定句の検索、用例との類似度や適合度を返す | 外部原文を確認する用途はある。検索単体や誤り位置が既知の推薦は、全文からの局所検出と同じ評価課題ではない |

根拠と実測条件は[先行研究の調査](prior-research.md)、解析部品の確認範囲は[解析器の調査](parser-investigation.md)に記録する。

採用判断には、全文から対象の語彙誤りを局所検出できるか、専門語・未見の正用への警告負担、初回起動と反復処理の速度・メモリ・保存容量、独自の構文例外を足さず保守できるか、コード・重み・データの利用条件を照合する。対象の異なる公表成績や接続の成功だけで決めず、対象と条件を明記した実測根拠を必要とする。

単体の検出成績を方式の足切りにしない。測定の目的は、各手法が何を捉え、目的に必要な何が欠けているかを具体例と処理段階から理解することである。低い成績だけでは、解析・参照資料・意味表現・教師の分布・判定条件のどこに原因があるかは分からない。既存の実測結果も、全文検出器としての制約と、他の処理を補う部品としての可能性を分けて残す。

方式間の共通の見逃し、一方だけが捉える誤り、訂正文への指摘を同じ原文位置で照合する。別の手法が拾えることは補完可能性の観測であり、単純なOR結合の採用理由にはしない。結合すると誤警告も増えるため、どの情報をどの段階で足すと不足を補えるかを仮説として明記し、必要ならその拡張に関する研究・実装へ戻る。組合せを既に調べた候補だけに限定しない。

## 現時点の判断

独自構文規則を含む旧extractor、未観測であることだけによる誤用判定、実測したTohoku＋Oddballnessのそのままの製品採用は見送る。旧試作はscratchへ隔離済みである。今回の結果をBERT全般の不可能性とは解釈しない。

既存の完成した検出器の不在を、開発を止める理由にしない。調査した構成原理を現行ライブラリへ接続し、必要な拡張を比較する。拡張の根拠が不足する場合は対応する研究へ戻る。たとえば、原句より高得点の代替を警告条件にする案は、過剰訂正と候補のない誤用の見逃しを指摘した研究に基づき、検出と訂正案を分ける構成へ見直した。

寺村誤用例集の利用条件、語彙カテゴリ、位置注釈を確認できたため、新規の大量の手作業注釈を開始条件とせず比較を進められる。データの形式変換は原注釈を保ち、曖昧な対応を推測しない。精度・速度の数値目標は利用場面と実測を踏まえて設定し、実験上の仮定を利用者の確定要件として扱わない。

専用GEDは誤り位置を明示した教師で学ぶため、Codexによる生成やMLM事前学習とは目的が異なる。ただし対象とする語彙誤りの独立評価がなければ、「専用BERTなら解決する」とも言えない。

## 次の比較と、拡張を判断する条件

同じ位置注釈と分割を使い、次の二つを比較する。現時点では製品採用を意味しない。

| 比較する構成 | 既存部分と今回確かめる拡張 |
| --- | --- |
| 用例からの適合と支持量による検出 | GiNZAの依存関係・見出し語・文字位置をそのまま読む。観測頻度に、同じ関係条件での意味的適合を加える効果を比較する。少数の特徴から警告を学習する部分は既存の分類器を使う |
| 専用の教師ありGED | 既存日本語BERTと標準token分類を使い、誤り位置の教師で学習する。全文を一度処理する構成の速度と語彙誤りの検出を測る。既に測ったtokenごとのmask反復とは計算量が異なる |

用例方式では、原表現の適合と比較資料の充足度を分ける。語や条件文脈の資料が不足する場合を、単なる低得点の誤用にしない。関係の両側を採点しても、一方の類義語との近さで組合せ全体を正用と認定しない。述語の類似性が誤用を救済する危険は、引き続き検証する仮説である。

原句より一般的な代替があるだけでは警告しない。訂正案は検出とは別に評価する。原文の適合を測る特徴だけで分離できなければ、用例の文脈比較など、その失敗に対応する既存研究へ戻って拡張を検討する。精度を確認する前に多数の方式を積み重ねない。

評価では、掲載行の重複を統合し、同じ学習者・同一全文が分割をまたがないようにする。寺村の語彙span、全誤りspan、未解決注釈、欠落位置、文全体への注釈を区別する。未注釈部分や既存の訂正文を完全な正用goldとは呼ばない。語彙位置の検出量、注釈外への指摘、訂正文1,000文字当たりの警告数、判定保留率、起動・反復処理・メモリ・容量を測る。閾値は開発用分割で選び、評価用分割で調整しない。

比較の共通単位は原文の文字位置とする。各方式のtokenの範囲へ得点を置き、同じ文字の得点は最大値で統合する。依存関係の端点間にある文字は埋めない。閾値を超えた連続文字を一つの指摘範囲にまとめる。全非空注釈の文字単位P/R/F0.5に加え、語彙注釈の文字再現率、1対1の範囲overlapによる到達率を報告する。広い一つの指摘で複数の誤りを全て検出済みにせず、余分な文字は文字指標へ反映する。候補の未生成・保留・位置不明による見逃しも分母から除かない。欠落位置は非空範囲の評価と分ける。

主比較は、開発用訂正文への警告対象文字数をそろえたときの語彙誤りの検出量とする。比較点は1,000文字当たり1・5・10文字であり、利用者の品質要件を意味しない。指摘範囲の結合で警告件数だけを下げられないよう、対象文字数で閾値を固定し、表示上の警告件数も併記する。全誤りF0.5の最大点は補助比較とし、その計算にも訂正文を含める。これらは既存注釈と訂正文を用いる代理指標であり、真の正誤を全て測る値とは呼ばない。方式・特徴・参照量・位置投影・閾値を開発用分割で決めてから、評価用分割へ一度適用する。

固定seedは`20261021`。寺村の既知全文3,054件を学習者・同一全文のvariantで265groupへまとめ、注釈未解決など318件を理由付きで主比較から除外した。学習1,669文／開発466文／評価601文で、語彙spanは1,054／307／380箇所。学習者・group・同一全文の分割間共有は0である。補助学習には、既存の開発・評価groupと別監査1,000groupを保留した教師訂正文2,933文を用いる。教師の広い誤用括弧をそのまま全tokenの誤り教師にはしない。

用例参照の初期資料には2019年2月のWikipediaを固定したMIRACL本文を利用できる。記事IDの固定hashによる抽出を本文や評価例を見る前に定め、同じ記事のpassageをまとめて扱う。本文抽出の欠落が存在するため正用goldにはしない。既存の373文書だけによる接続確認を、汎用性の実証に代えない。
