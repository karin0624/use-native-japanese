# 目的と設計の見直し

AIが出した誤った日本語をリアルタイムで位置付き指摘し、可能なら訂正案を出す。中心となる問題は「重複を畳む」のような、用例に裏付けられない語の使い方である。スクリプトからの自動呼び出しと高速な反復実行を必須とし、textlintへの接続、将来の商用利用を考慮する。

## 語彙用法の同一性からの再検討（課題15・2026年10月27日 日本時間）

比較するのは、**同じ出現の述語語彙と相手語彙が、どの結び付きで使われたか**である。
用法の共有条件を先に定め、正しい語彙・関係を与えた後段で適切な指摘と用例支持が成立する見通しを確認してから、必要情報を既存解析から取得する。
解析情報を取得できることだけでは、部品の選定や製品採用を決めない。
解析器が返したラベルや現在の照会キーを、そのまま日本語として正しい比較条件とはしない。
この節が課題15の現在の設計判断であり、以下の過去の案・限定検証は各時点の記録として読む。

### 共有すべき用法と保持すべき区別

「ネックレスをつける」と、同じ装着対象を取り立てた「ネックレスもつける」は、用例の支持を共有する。
これは利用者の好みで決める採否ではなく、同じ語彙的な使い方を比較するための条件である。
一方、「私もつける」の「私」は主語であり、「も」を一律に「を」へ置き換える規則では実現できない。
取り立ての表記と、その名詞が当該述語に対して持つ関係を分け、関係判定は既存解析へ委ねる。

| 比較する内容 | 同一化と区別の期待 |
| --- | --- |
| つける／つけています | 同じ述語語彙として照合する。活用・助動詞を含む原文の範囲は保持する |
| ネックレスをつける／ネックレスもつける | 同じ装着対象の関係を共有する。取り立ての差だけで用例支持を失わせない |
| 明示された主語／目的語の関係 | 明示ガと明示ヲを直接共有しない。格が隠れた用例との互換検索には、後述する近似の限界が残る |
| 主節と連体節にある語 | 各出現の述語・相手・係り先を保持し、別節の語を寄せ集めない。被修飾名詞を目的語と自動認定しない |

[日本語UDの設計原典（Tanakaほか2016 §4）](https://aclanthology.org/L16-1261.pdf)は、は・もで格助詞が隠れる場合にも文法上の関係を与え、取り立てた目的語にも同じ関係を付ける。
原典の`dobj`はUD v1の名称であり、現行の`obj`と名称を区別する。
一方、[日本語UDの構築研究（浅原ほか2019 §4.2・§6.2）](https://www.jstage.jst.go.jp/article/jnlp/26/1/26_3/_pdf)は、既存コーパス変換の近似や、は・もに対する項構造情報の必要性を述べる。
したがって、現行予測の`nsubj`と`obj`の差だけを、装着対象と主体の正しい区別とみなせない。
UDは引き続き既存表現の候補であり、この不足からPAS全体の導入を必須とはしない。

### 比較の契約と解析器の責務

比較するのは、同じ原文出現の述語語彙、相手の名詞語彙、その結び付きである。語彙・文法上の役割・原文の範囲を分ける。「不一致」の「不」を落とさず、「読み替える」を「読む」へ縮めず、可能・相・丁寧さを一律に述語語彙へ足さない。引用用の句全体を、そのまま比較する語の列にはしない。

**構造と、その構造に対する役割・格・態は、整合した一つの解析経路から取得する。** 一方の解析器の主辞・係り先と、異なる単位を前提にした別の解析器の文法情報を、項目別に採用しない。特定の解析器の出力を保持することは、限定比較で変数を固定する条件であり、利用者の最終要件ではない。必要なのは原文の正しい使い方を取得することである。

既存解析が保持する語構成、並列、名詞項、連体修飾、節間関係を区別する。並列の辺そのものを名詞項へ変換しない。連体の被修飾名詞を目的語とみなさず、主語・目的語・引用の説明先を同一の役割だと断定しない。照応用の「名詞項候補」、内部型のCF_PRED、品詞、格候補の非空のいずれも、単独では検査対象を決めない。

語彙取得には、同じ原位置に対応する既存辞書の語彙単位・辞書形を利用する案を検討する。辞書側から係り先や格を作り直さず、主辞一語に縮めて複合名詞や造語の構成を失わない。名詞と述語で必要な情報が違うため、名詞の表層範囲と述語の基本形を別に定義する。表示用の範囲、検索用キーワード、文法上の用言見出しは、同じ語彙単位を保証するものではない。

### 格が明示されない場合の照合

現在の照合候補は、**既存文法が返す原候補集合を入力・参照の双方に保持し、共通候補がある用例を対称に検索する**構成である。語彙・端点・関係の方向を固定し、入力候補をS、参照候補をTとして `S ∩ T ≠ ∅` を互換条件とする。

[KNPの既存候補処理](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/case_data.c#L177-L303)を追加公開した限定接続では、「を」の{ヲ}と「も」の{ガ,ヲ,ガ２}を取得した。明示{ガ}と明示{ヲ}は交わらない。広い集合を橋に群を推移的に併合せず、候補なしを全格へ置き換えず、返却された端点が異なる候補を元の名詞へ流用しない。

「この完全一致を確かめる実験は行わない」で単一PASが実験をガ格としたため、PASの値が文法候補内にあるだけで候補を一つへ縮める方針は撤回した。候補の交差にも、未格の用例群へ実際の主体と対象が混在する近似が残る。支持元の群と原文を保持し、名詞一般化による支持を正解の格として解析へ書き戻さない。

[京都大学の注釈基準§3.2–3.5・§3.7.1](https://nlp.ist.i.kyoto-u.ac.jp/nl-resource/corpus/KWDLC-1.0/doc/rel_guideline.pdf)の格は文中の出現形に対する値であり、原形の意味役割とは同一でない。受身のガ格と能動のガ格を混ぜないため、既存`set_pred_voice`の計算値を比較条件に使う案を保持する。計算0は能動の正解を意味せず、可能も0になる限界がある。独自の能動格変換、全役割の細分化、ゼロ照応を追加要件にしない。

### 限定接続と全本文の確認で判明したこと

入力と参照に同じ契約を適用するため、通常Juman++→KWJA wordの公開lemma保持経路→NIL形式→KNPを用いた限定接続を検証した。元の品詞や意味情報を書き戻さず、既存計算の構成ID・格候補・述語自身の計算態を追加公開した。用例追加・閾値調整は行っていない。

同じ55自然本文による比較では、「ネックレスもつける」「パンも食べる」の名詞一般化による支持が回復し、固定した三つの負対照に新たな支持は付かなかった。ただし「着る／服」の支持元が誤付着した「色」である例もあり、数値上の支持を正しい用例取得と混同しない。直接一致の成立と未収録名詞への一般化も別の確認である。

その後、既存textlint接続が取得する段落・見出しの固定1,042区間（1,040種類の全文）へ同じ処理を適用し、全原文と全採用用法を分担して読んだ。警告件数の減少を精度とせず、元の語・節・位置へ戻って確認した。次の不備があるため、**この接続をそのまま製品へ採用しない。**

| 不備 | 原因と扱い |
| --- | --- |
| 「構造決定と格解析」等の列挙を独立用法にする | 元のP（並列）を読み落としていた。既存の並列情報を読んで、その辺自体を名詞項へ変換しない最小修正を独立レビュー済み。元のPの予測自体が正しい保証とはしない |
| 「不一致」から不が落ちる、述語「含む」へ後続のCが混ざる | 文節のキーワード集約を語彙取得へ転用した不備。名詞を主辞と内容語IDの包絡で作り、述語を全文節の内容語列で作る候補は撤回する |
| 「終える」が付属だけの独立文節になり、名詞述語のfallbackへ入る | wordの固定単位とnativeの全文化形態規則・文節判定が整合していない。注釈の単純な除外では直らない |
| 有効なUTF-8入力から不正な文字列を生成する | nativeの疑似代表表記生成が読みの長さを越えて切断したCの不具合。読み領域と文字境界を検査し、変換できない場合は既存の初期表記を保持する修正を独立レビュー済み。保存された失敗1件を再取得し、元の失敗記録も保持した |

[KNPの内容語正規化](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/read_data.c)はキーワードを集約する処理であり、[用言見出しの生成](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/case_ipal.c)とも異なる。後者へ全面置換すると可能・相・受身を含み、単純な基本句化では複合動詞を失う。API名に「正規化」とあることを採用根拠にしない。

構造の接続では、現設定はwordの文節・基本句の注釈を読まず、11形態属性・意味情報と固定境界・係り先を読む。nativeは形態規則を文全体へ適用した後、固定文節で文法情報を再計算する。同じ原文位置を保持していても、二つの解析の単位が整合するとは限らない。`-read-feature`も形態解析の凍結ではなく、単に付け足す修正にはしない。

### 次の工程と採用条件

1. **語彙と構文の責務を揃える。** 語彙辞書から取得する単位と、役割・格・態を生成した解析単位の対応を定める。現在確認しているのは、既存Sudachi Cの語彙単位と、native自身が整合した単位を決める経路である。特定の解析器への全面変更はまだ決めない。
2. **観測済みの不足に対応する限定検証を行う。** 複合動詞・可能／相・接頭部・名詞構成の保持と、固定単位の不整合を分ける。文節を切り出して語彙解析すると文脈で品詞が変わる例があるため、同じ原文の文を使う。全本文や別モデルの再試行を先行させない。
3. **同じ契約の入力と参照で用例支持を確認する。** 既存55本文と対照を再利用し、正しい用例の共有、誤支持、語や関係の取り落としを原文で確認する。旧v8索引と新表現を混用しない。
4. **成立した変更を通常の本文・実行環境・配布経路で確認する。** 主な固定資源の個別gzip合計は約466MBであり、単一npm配布物への同梱成立は未確認。既存のLFS・npm実体同梱方針を無断で変えず、提供方法も採用前に具体化する。

製品本体・モデル・配布参照は変更しておらず、mainはPR #17の状態である。全Markdownの構文不備修正は未完了。新しいwarnや保留出力、語別例外、用例追加、原文の書換えで不備を隠さない。今回の設計・限定成立を元の課題の完了とは扱わない。

## 混同してはいけない問題

| 問題 | 今回の扱い |
| --- | --- |
| 語の組み合わせとして使われているか | 検出したい問題の中心。意味を推測できることや類義動詞の用例を、原動詞の使い方の実績としない |
| 名詞自体が新しい、参照資料にない | 組み合わせの誤用とは別。名詞単体の未収録から、その対象への述語の使い方を誤りとしない |
| 用例のある正しい表現同士で意味が違う | 今回の検出対象ではない。「友人に話す／友人について話す」の区別を必要機能にした判断を撤回する |
| 採用した参照資料に一致する用例がない | その資料と比較条件に対する観測結果。日本語全体での不存在や、誤用であることの証明ではない |
| 解析や索引が入力を正しく処理したか | 機構の検証。成功しても、選んだ単位が目的に合うことや誤用検出性能を示さない |

用例・コーパス・三つ組・単語ベクトル・選択選好・BERT・検索は候補手段である。参照会話のassistantの提案を利用者の確定要件にしない。一方、利用者は元の会話で未観測を誤りと断定しないこと、名詞側の一般化の可能性にも言及している。今回の訂正を、それらの永久的な禁止や過去の調査の破棄へ読み替えない。

特定分野での用例も支持材料になる。一般文と技術文の文体適合、比喩表現、一般的な意味理解を完成条件に加えない。訂正案は任意であり、原句より頻出の表現があることは訂正の必要性を示さない。

## どこで判断が飛躍したか

1. **情報を保持する表現と、検査すべき単位を混同した。** 一部の語と関係を同じkeyへ保存できることから、全2〜4 nodeの未観測を警告候補とした。句読点や助動詞を含む全部分構造が、指摘したい使い方の一件になる根拠はなかった。
2. **参照範囲の不足を、判定機構の不足へ読み替えた。** 速度・保存量の計測用に作った先頭1,000段落・45記事での未観測から、一般的な警告分類が必要とは言えない。
3. **対象外の違いを必須機能へ加えた。** 正用同士の意味差や一般的な多義性から、文脈モデルが必要という話へ広げた。今回の誤用検出に生じた不足の証拠が先に必要だった。
4. **注釈の存在と、対象問題への適合を混同した。** 固定4入力には名詞単体への注釈や「い→いい」「見ますか→見えますか」という訂正があるが、それだけで対象の連語誤用の対照になるわけではない。位置注釈があることを入力選択の根拠にし、何を確かめられる対照かの確認が不足した。
5. **工程への適合だけをレビューした。** 検証コードは固定計画に沿っていたが、計画自体が元の目的を確かめるものかを十分に点検しなかった。

[固定4入力の結果](minimal-validation.md)は撤回しない。ただし、そこでの未観測の広がりを特定の追加機構が必要という結論へつなげた解釈を訂正する。保存済み参照の確認では、対象の二語関係そのものが収録されておらず、存在する同じ関係を索引が失った証拠はなかった。資料を増やせば解決するという結論も、まだ出ていない。

## 今回の比較と残る判断

比較の中心は、原の動詞・形容詞等が、どの語と、どの結び付き方で使われたかである。[比較単位の研究](prior-research.md#語の使い方と列挙できる構造の区別)から、単純な名詞‐格‐動詞型では語彙単位間の関係を核とし、句全体の修飾を一律に一致条件へ足さない根拠を得た。対象の関係を定義することは、照合前に疑わしさを判定して候補を減らすこととは別である。

「つける／つけています」は同じ動詞を使った用例として、既存形態素解析の基本形・代表表記で照合する。元の語を保つことは、助動詞等を含む句全体の完全一致を要求することではない。原文や述語句全体は引用のために保存するが、保存項目を全て照合条件にしない。

格関係と、それが助詞等によってどう記されるかは別の情報であり、動詞の正規化からも分離する。必要なのは同じ出現の語と関係を既存解析から読むことで、独自の助詞対応表や構文補修ではない。狭義の連語に分類されない自由な語の組み合わせも使用実績として参照する。完全な複合述語IDや意味等価判定をこの接続の前提へ加えない。

固定入力・参照表記・結果による判断・予算は[検証計画](lexical-usage-validation.md)に定めた。参照不足と比較条件による取り逃しは、未観測という結果だけでは決めず、原文と公開値まで戻って確認する。未知入力の全文性能は後続で検証し、この対照の成功を一般性能へ広げない。全量処理、警告抑制、追加モデルを先に実装しない。

- 固定した評価資料と元注釈。教師訂正文を完全な正用goldとせず、一般的なGEDの成績を対象の連語誤用の成績へ読み替えない。

### 照合する内容と原文への対応

検査するのは、同じ出現の述語語彙と相手の名詞語彙が、選んだ関係条件で結び付く使い方である。形態素分割と検査する語彙単位を同一視せず、原文位置、語彙内容、活用形、表示に使う範囲を区別する。

- 述語の語彙内容には、サ変の「削除する」「再利用する」の内容名詞も含める。一律に「する」へ縮めず、述語を構成する名詞を相手名詞として一般化しない。
- 活用前の語彙を照合し、活用形・助動詞等を含む原文の範囲は表示と監査のために保持する。保存した全要素を一致条件にはしない。
- 相手の名詞句が原文のどの出現かを保持する。比較する名詞語彙と、その句の全修飾語・指示対象を同一視せず、名詞句全体の完全一致や共参照解析を必須にしない。
- 原の名詞と述語の関係と方向を保持する。別節・別の係り先の語を寄せ集めて一つの使い方にせず、複数条件を比べる場合も参照の同じ出現で成立することを求める。

[Park・Seraku・Kiaer 2016 §2.2](https://doi.org/10.1016/j.heliyon.2016.e00189)は、名詞句全体を取る統語関係と、名詞・動詞の語彙的な結び付きを区別する。[京都大学の公式注釈基準 §2.1・§3.7.6](https://nlp.ist.i.kyoto-u.ac.jp/nl-resource/corpus/KWDLC-1.0/doc/rel_guideline.pdf)は、タグ単位と意味関係を担う自立語部分を分け、動作的なサ変名詞にも項関係を認める。これらは語彙内容と句全体を区別する根拠であり、全複合述語の境界を独自に決める規則ではない。

### 関係条件の範囲

当初の対象は、原文に明示された名詞と動詞・形容詞等の述語との主語・目的語などの結び付きである。それぞれの関係を保って検査する。述語を含む節が名詞を修飾している場合も、節内の対象関係は検査する。ただし、節の被修飾名詞との組を、修飾関係があるという理由だけで新たな検査対象に加えない。目的語が得られたら他の項を捨てる条件ではなく、その出現の関係を選ぶ。解析上の一つの依存辺に限定する意味ではない。

| 確認した文 | 語彙検査の対象 |
| --- | --- |
| このプリセットが名詞・述語を返す | プリセットと返すの主語関係、名詞・述語と返すの目的語関係をそれぞれ検査する |
| 名詞・述語を返すtextlintプリセットです | 名詞・述語と返すの目的語関係を検査する。返すとプリセットは、同じ連体構文の用例を照合する別条件であり、目的語関係へ変換しない |
| 彼が精度を食べる | 精度と食べるの明示された目的語関係を検査する |
| 彼が食べた精度 | 現行は食べるで精度を修飾する用法として照合する。精度を目的語と推定する方式ではない |
| 精度が高い | 形容詞を述語とする主語関係も対象。動詞だけに限定しない |

同注釈基準§3.5は、連体修飾をガ・ヲ等に対応する内の関係と、それ以外の外の関係に分ける。説明・呼称だけでは内・外は決まらず、構文が成立することも独立した語彙検査の必要性を示さない。現行の`acl`と`head`方向の保持は原構文の保存であり、目的格へ変換している既存バグはない。上の連体文のプリセットを主体と断定しない。

相手の名詞語彙は現行と同じ普通名詞・固有名詞を扱う。「彼」のような代名詞の指示対象を解決し、その対象の語の使い方として照合する機能は加えない。解析器が保持する主語関係と、語彙照合へ渡す対象はここでも区別する。

対象へ加える前に、後段で適切に指摘できる見通しを得る必要がある。現実装では次の二つは別の照会・別の一般化群になる。

```text
精度を食べる → 食べる / obj / 精度 / dependent
食べた精度   → 食べる / acl / 精度 / head
```

`group_key`は名詞語彙だけを取り除き、依存ラベルと方向を保持する。したがって、前者の用例を後者の目的語として利用する経路はない。配布参照にも`食べる/obj/dependent`と`食べる/acl/head`の群が別々にあり、後者の照会自体は実行できる。同じ`acl/head`は食べる側・食べられる側等を区別しないが、これらの実装事実だけで指摘が不適切・実現不能とは結論できない。元の構文ごとに実用例を照合する方式も成立し得る。構文間の共有能力、照会処理の存在、指摘の妥当性を区別する。

後述の限定確認では、連体形の正用・誤用を分ける成立例があり、現行解析から位置付き指摘まで既に接続されていた。「連体形を判定する仕組みがない」「解析だけが未対応」という説明を訂正する。問題は、指摘の妥当性を確かめず対象を広げ、後から採否を利用者へ選んでもらおうとした工程にあった。格・PAS変換や直接形容詞修飾の採否も、必要性を示す前に決めない。ここで確かめるのは利用者へ出す指摘の妥当性であり、訂正文生成の実装有無へ論点を移さない。

### 形式に依存しない語彙単位

名称・識別子は、形態素解析で細分割されても、その内部で独立した日本語述語と相手名詞の用法を作らない。`textlint-rule-preset-native-japanese-0.1.0.tgz`は名前全体を一つの検査語彙単位として扱い、内部の`native`や`japanese`を別々の語彙用法へ分割しない。名前全体が周囲の文章で持つ関係は別に保持する。

同じ表示本文を`.md`と`.txt`で検査した場合、同じ語彙単位・関係を得ることを要件とする。Markdown構文の読み取りと原文位置への対応は入力適応層の役割であり、語彙単位をMarkdownの装飾やコード範囲の有無で変えない。コード内部の自然文を除外する仕様は採用しない。

これは入力形式に依存しない単位の要件であり、全ASCII文字列を一語とする規則や特定の正規表現、NER等の実装方法を決めるものではない。この時点では既存解析からの単位・構成範囲の取得方法は未決だった。後述の限定検証と区別し、上記研究が識別子の自動判定を実証したとも扱わない。

### 指摘の成立から解析要件を決める

確認した仮説は、原文に対応する語彙・関係を正しく与えれば、参照への照会と名詞一般化で、対象の誤用と正用に妥当な指摘・無指摘を返せることである。まず後段だけを確認し、成立した判定に必要な情報を定めてから、現行解析との接続を確かめた。構文解析に起因する失敗と、比較単位・一般化方式に起因する失敗を混ぜない。

`test_reference.py`の索引・群計算の整合性や、自然資料での容量・接続確認は再利用するが、それだけで指摘の妥当性を確認済みとはしない。特定の正用への支持が情報追加で回復した結果も、確認した範囲を越えて一般性能の証拠にしない。全件正答は要求せず、特定の参照への未収録と方式の不備を分ける。

既選定のTeacher `teacher:4581`と正用対照について、解析器を介さず原語と目的語関係を現v3の後段へ渡した限定確認を行った。「ネックレス／着る」は類似度0.131で指摘、「ネックレス／つける」は0.364で無指摘となった。別条件の「付ける」は0.290で正用にも指摘が出た。三照会ともBloom陰性で、閾値0.35は不変。原語と関係を既知として与えた一対の結果であり、連体形・新しい語彙単位・解析経路への適合を示したものではない。

支持の理由も確認した。「着る」群の3名詞のうち平均へ参加したのは「権威」だけ、「つける」は帽子・スカート等を含む20名詞の平均による支持だった。結果の分離だけから名詞群の代表性まで認定せず、直接用例の不足と一般化の成否を区別する。現v3正本はこの確認では取得できず、保存済みv1正本の該当3群を用いたが、名詞数・参加数と再構成した平均の全成分が現v3保存値に一致することを確認した。旧正本を現判定へ差し替えてはいない。独立レビューでも、この限定結果と実装の整合性を確認した。

連体形については、[NLB公式マニュアル§9.2.2](https://nlb.ninjal.ac.jp/static/pdf/NLB.manual.v.1.40.pdf)に、格助詞付き名詞と動詞の組、動詞が後続名詞を修飾する組を別々に検索する先例がある。[Erkほか2010 §3–3.1](https://aclanthology.org/J10-4007/)も、述語と統語関係を固定した用例名詞による一般化を扱う。意味格へ統一せず、原構文ごとに照合する根拠として参照した。検索機能や他言語の研究成績を、日本語連体形の検出精度の証拠にはしない。

この原理を現v3参照・既存ベクトル・閾値0.35のまま確認した。出力前に固定した15照会と、既収録用例の支持を確かめる追加の対照から、次の結果を得た。

| 比較する組 | 明示目的語の形 | 連体形 |
| --- | --- | --- |
| 精度・食べる（利用者提示の誤用） | 指摘、0.210 | 指摘、0.281 |
| パン・食べる（正用） | 無指摘、0.361 | 指摘、0.056 |
| ネックレス・着る（既選定の誤用） | 指摘、0.131 | 指摘、0.322 |
| ネックレス・つける（正用） | 無指摘、0.364 | 指摘、0.237 |
| 服・着る（参照に実在する正用） | この追加確認では対象外 | 索引が一致し、無指摘 |

「着た／つけたネックレス」は既存注釈の制御変形であり、新しい独立した人手正解ではない。「服・着る」は既収録用例を支持する能力の確認であり、未収録名詞への一般化の成功例ではない。ほかの固定照会も残し、支持された表記や入力だけを選び直していない。

原文まで調べると、「食べる」の連体群は「こと」「一節」の2名詞で、平均へ参加したのは「こと」だけだった。固定元本文で「食べ」を含む全16区間にも、食べ物や人を被修飾名詞とする同条件の用例はなかった。「つける」の連体群にも装着対象の名詞がなく、行為者・内容・状況等が混在した。ただし、この混在が誤指摘の原因だと示す比較はしていない。該当8群の名詞数・参加数と、旧正本から再構成した平均は現v3と全成分で一致した。旧正本と現v3の来歴全体が同じという意味ではない。

したがって、現在の後段には「着た服」を支持し「着たネックレス」を指摘する成立例がある。「食べたパン」等への誤指摘は、適切な用例が元資料にも不足する条件での結果であり、連体形全体を扱えない根拠にはしない。すべての連体関係の検査や、格推定の追加が必要という結論にも広げない。

次に、この判定に必要な述語・名詞の基本形と品詞、元の関係と方向、原文位置を現行解析が取得するか、4原文を事前に固定して`Inspector.lint`で確認した。「彼が精度を食べる」「彼が食べた精度」「彼が着た服」「彼が着たネックレス」はすべて、語彙・関係・方向・位置と後段単独の判定が一致した。現行解析はこれらの連体形に既に対応しており、この4文のための解析機能追加は不要である。後段と実経路の保存結果はfresh contextで独立レビュー済み。

元のREADMEの「返す／textlintプリセット」も保存結果と出典まで確認した。語彙・`acl/head`・原文位置は一致しており、「プリセットを返す」という誤解析ではなかった。名詞の両成分にベクトルはあるが、同条件群の平均へ参加したのは「かたち」「松」の2語で、類似度0.091となった。旧正本の群の名詞数・参加数・平均は現v3と一致した。この一件はREADME側の解析失敗ではなく、現参照での支持不足と分類する。節内に目的語が既にあることから、別の修飾用法を誤りと判断した説明を訂正する。参照側に名詞の取り方が疑わしい記録もあったが、平均へ不参加であり、今回の類似度低下の原因にはしていない。

必要情報を後段の判定から導く前提は、この限定範囲で確認できた。課題15では、引き続き元の語彙単位・関係・位置を失う不備の修正へ進む。未知の名称や複合述語の単位を既存解析から取得する方法には、先行調査を再利用する。比較単位を変える場合は後段への影響も限定確認する。構文ごとの用例共有、新しい対象関係、全入力の精度を、この成立例から承認済み・検証済みとはしない。

この工程では用例を追加せず、モデルを変更しない。現行の支持条件であるBloom陽性または類似度0.35以上、支持なしの通常error、処理異常のsystemerrorを維持する。正しい比較情報を与えても目的を満たせない場合は、必要な設計変更を具体化して相談し、解析器だけの変更で解決したことにしない。

### 先行して行った語彙単位の調査記録

以下は指摘の成立を確かめる前に進めてしまった調査の記録である。後段の限定確認を経て、必要な語彙単位の取得に関わる範囲で再利用する。[国立国語研究所の長単位規程](https://repository.ninjal.ac.jp/record/2871/files/LR-CCG-10-05-01.pdf)は、語として働く記号を含む名称やサ変の内容名詞と「する」を、一つの長単位として扱う。[UD Japanese GSDLUW](https://github.com/UniversalDependencies/UD_Japanese-GSDLUW)は、この長単位を依存解析の語とし、基本形・品詞・依存関係を付与する。長単位の定義への適合と、未知の名前をモデルが正しく認定することは別である。

[Stanza 1.15.0](https://github.com/stanfordnlp/stanza/releases/tag/v1.15.0)の公式`gsdluw`既定構成を隔離環境で確認した。公開Word自体がパッケージ名を三つに分け、周囲の「配布する」との目的語関係が末尾の断片に付いた。既知文の「握り潰す」も分割され、必要な述語語彙を保持できなかった。別の文の「表す／表わす」は関係と位置を保持した表記差であり、解析失敗へ数えない。独立したレビューでも、前二件は接続実装ではなく公開解析の不足と確認した。製品への導入・全文処理・参照の再構築はしていない。

[松田らの長単位解析系](https://www.anlp.jp/proceedings/annual_meeting/2022/pdf_dir/PH1-5.pdf)は、形態素辞書の単位を分割せず、学習した関係で長単位へ結合する。当初の調査では、公開モデルの依存条件が古く、現環境での教師データ変換・既存正規化処理の再利用を確認できていなかった。この時点では重み取得・実行・再学習をせず、後段の判定を先に確かめた。

後段の限定確認後、同方式の固定モデルをspaCy 3.8.16とspacy-transformers 1.4.0の隔離環境で確認した。既存readerによる読込みは成功し、辞書Cが保持した「握り潰す」と、明示主語・目的語・連体関係は取得できた。一方、パッケージ名は版番号付近で5片に分かれ、NUMと分類された末尾のtgzだけが「配布する」に結ばれた。名称全体の語彙内容と外部関係を保持する要件を満たさず、製品へ採用しない。必ず一つのparser tokenにすることを要件とするのではなく、内部の形態素分割と検査語彙単位を区別する。互換警告を保持し、追加学習や別構成の試行は行っていない。

### 先行して提案した追加学習案（保留）

以下は、一般的な形態素解析の未知語処理と後段の品詞上書きを十分に切り分ける前に提案した案である。利用者から必要性の再調査を求められたため、追加学習を次工程とする判断は保留した。学習が必須だという根拠にはしない。

検証したモデルは、名称の先頭片を既にPRODUCTと認定していた。NERを追加するだけでは残りの版番号・拡張子や外部依存の不足を解消できない。同論文§3.2も固有表現と長単位の境界を区別しており、NERの範囲を一律に検査語彙とする規則は追加しない。

変更案は、同じ方式の境界・品詞・依存予測を、既存注釈から作る教師データで追加学習することである。取得済みGSDLUW trainには、PRODUCTと単一長単位が一致する注釈が499箇所あり、記号と数字を含む名称もある。既存package-lockにある実tarball名38種を、注釈済みの名詞出現へ置き換え、名詞品詞・外部依存・周辺文のgoldを保持する。既知境界をSudachi列へ対応付けてsubtok教師へ変換し、spaCy標準学習と既存結合処理を再利用する。名称の辞書登録や、生成文の用例支持DBへの追加は行わない。

[Gulordavaほか2018 §2](https://aclanthology.org/N18-1108/)は形態統語条件を保つ語の置換を扱うが、日本語の技術名称解析への改善効果を示すものではない。生成文を学習に使う効果は今回確かめる仮説である。名称系列と元文系列の両方を学習・評価で分け、元READMEの名前を学習へ入れず、境界・名詞品詞・外部関係・原文位置と通常の日本語述語の保持を確認する。既存DocBin/注釈APIを使う形式変換の開発が必要であり、既存モデル接続だけの修正からは工程が広がる。

この案は未実施で、方針変更の相談対象である。GSDLUW注釈のCC BY-SA 4.0と原文の権利を分けて扱う。同じモデル構造なら教師データ数に比例して配布モデルが増える方式ではないが、今回の実測は起動約13秒、1文約75–100ms、最大RSS約3.17GBであり、追加学習で軽くなるとは見込まない。語の表記を既存normalizerが変えることだけを失敗と決めず、原文範囲と入力・参照での同じ語彙内容の照合を確認する。

### 識別子の語彙範囲を元の解析から得る判断

元READMEの段階別確認では、Sudachiはnativeとjapaneseを既にNOUNとして返し、後段morphologizerがjapaneseをVERBへ変えていた。「英単語の名詞分割ができないため追加学習が必要」という診断は撤回する。追加学習案は未実施のまま保留し、語彙単位とparser tokenを分けて検討する。

既存RegexOovProviderへ公式hyphen形式、続いて[UAX #31のASCII profile](https://www.unicode.org/reports/tr31/tr31-45.html)を設定して隔離検証した。UAX31設定では全名の候補選択とREADME等の外部照会に成立例を得たが、別のファイル名のNUM化を残し、さらにリポジトリ全体の本文監査では、新たな偽述語や既存関係の欠落を確認した。前段のtoken分割を変えるOOV案は不採用とし、その製品候補の変更を取り消した。名称境界が得られることを、後続解析全体の改善と同一視しない。

解析後にspaCyの標準mergeで名称tokenをまとめる案も、Node.jsを含む「使う」の名詞句から全名が欠けたため不採用とした。元のjs→以上のcompoundが提供していた句をmergeで失い、rootの辺だけが残っても必要な句の範囲を得られなかった。

採用する設計は元Docを変えず、照会・表示の語彙範囲だけを識別子Spanへ対応させる。構造文字を含む同じASCII profileを`Doc.char_span(strict)`で取得し、同じ名前内部の辺を独立用法から外す。対象の役割は元の公開依存関係から読み、元端点tokenのPOS/tagを保持し、句も元tokenから取得する。名前の一部を含む句は名前全体を含む範囲に広げ、外側の普通語も保持する。v6で表示用の包絡Spanと比較用の選択Tokenを区別し、表示範囲の途中に含まれるだけの非選択Tokenを照会に加えない。範囲を広げた述語句と名詞句が重ならない場合は、選択Tokenが属する識別子を原文表記一項、それ以外を選択Tokenのlemmaで照会する。重なる場合はその関係の両端とも範囲拡張と一項化を行わず、元の公開句を表示し、識別子へ投影しない選択Tokenのlemmaで検査する（[現在の構成](architecture.md#原文から位置付き指摘まで)）。範囲と表記をそろえるために品詞や辺を変更せず、語別一覧も加えない。両端の位置と全Queryが完全に一致するRelationは、元の順序を保って一意にする。

当初のSpan.rootのPOS/tagで端点の型を読み替える案は、限定16入力では成立したが、リポジトリ全体の意味監査で新たな偽用法3件や外部関係の消失を認めたため不採用とした。範囲・表記の統一に型の読み替えは不要であり、元の品詞判定を保つことで、型の変化を理由に新しい辺を採用することを避ける。

F5では、元の誤った句を全名へ広げることで、両端に同じ名前が混入する重なりを観測した。異なる語彙として対応できない変換を避けるため、この場合は元の句・lemmaを保持する条件を加えた。関係を削除せず検査を続け、新しい重なりを防ぐ。元の句解析が既に誤っている問題自体は残る。

品詞の読み替えを撤回した方式では、元の限定入力の期待と元Doc不変を確認した。これは語彙範囲・照会列の変換の限定検証であり、用例支持、名前一般の正確さ、既存構文問題の解決を示さない。リポジトリ全体の確認、同本文からの参照再生成、最終CLI/CIの成立は、この限定結果に含めない。用例追加や学習は行っていない。

### 元の依存役割と品詞を分ける接続修正

現行v8では、元Docのnsubj/obj/iobj/oblが示す名詞項とそのheadを、
名詞役割と述語役割として直接受け取る。acl/amodは被修飾側が名詞役割となる逆方向を保つ。
公開役割だけを用法照合へ変換するため、「再利用」がNOUNでも既存の目的語・主語・斜格関係を失わず、
「基本形」がADJでも元の目的語のまま渡す。標準UD品詞は両側とも元値のまま照会キーへ保存する。
同じ語のNOUN/VERB等を暗黙に統合せず、入力と参照は同じv8で生成する。

名詞述語・数量・名称も、元の主語等の公開関係がある場合は候補になる。
これは全名詞を動作と認定したり、名詞同士のnmod/compoundを新しく列挙したりする変更ではない。
v7で残していた他ラベルの品詞経路は、節間修飾や語構成まで用法へ変換していたためv8で廃止する。
[UD公式分類](https://universaldependencies.org/u/dep/index.html)が区別する名詞項と節間修飾・名詞修飾・語構成に沿い、
advcl/nmod/compoundを端点の品詞だけで独立の名詞述語用法へ変換しない。
節内の主語・目的語・oblと、別条件としてのacl/amodは保持する。
nmod/compoundの句構成探索は維持するが、本来の用法がnmod等へ誤解析された場合は回復しない。
件数減少を改善とは呼ばず、元解析の不足と接続の読み違いを区別する。
語別例外、aux必須条件、助詞や用例による構文の推測は加えない。
元の句選択・原文位置・識別子投影と重複guardを保ち、元解析の誤った辺や語彙境界の問題は別に残す。
