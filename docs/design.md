# 目的と設計の見直し

AIが出した誤った日本語をリアルタイムで位置付き指摘し、可能なら訂正案を出す。中心となる問題は「重複を畳む」のような、用例に裏付けられない語の使い方である。スクリプトからの自動呼び出しと高速な反復実行を必須とし、textlintへの接続、将来の商用利用を考慮する。

以下は2026年10月22日の設計見直しの記録である。その後の実装・検証の完了範囲は[工程表](implementation-plan.md)、実測と残る制約は[検証結果](runtime-validation.md)に記載している。

この見直しの時点では、[二入力による限定照合](lexical-usage-validation.md#最終結果)、[既成辞書への接続](reference-preparation.md)、[全文検証](coverage-validation.md#全文検証で判明した接続上の不足)を完了した。活用の正規化と原文位置の対応は成立した一方、主辞一形態素だけの比較では元の語を失う例があり、列挙した関係の種類にも混在があった。既存の語彙正規化・PASの対象取得・辞書欄の意味を再調査し、[接続の検証計画](normalization-connection.md)を定めた。相・丁寧さを含む述語句全体の一致を要求し直す意味ではない。

## 混同してはいけない問題

| 問題 | 今回の扱い |
| --- | --- |
| 語の組み合わせとして使われているか | 検出したい問題の中心。意味を推測できることや類義動詞の用例を、原動詞の使い方の実績としない |
| 名詞自体が新しい、参照資料にない | 組み合わせの誤用とは別。名詞単体の未収録から、その対象への述語の使い方を誤りとしない |
| 用例のある正しい表現同士で意味が違う | 今回の検出対象ではない。「友人に話す／友人について話す」の区別を必要機能にした判断を撤回する |
| 採用した参照資料に一致する用例がない | その資料と比較条件に対する観測結果。日本語全体での不存在や、誤用であることの証明ではない |
| 解析や索引が入力を正しく処理したか | 機構の検証。成功しても、選んだ単位が目的に合うことや誤用検出性能を示さない |

用例・コーパス・三つ組・単語ベクトル・選択選好・BERT・検索は候補手段である。参照会話のassistantの提案を利用者の確定要件にしない。一方、利用者は元の会話で未観測を誤りと断定しないこと、名詞側の一般化の可能性にも言及している。今回の訂正を、それらの永久的な禁止や過去の調査の破棄へ読み替えない。

特定分野での用例も支持材料になる。一般文と技術文の文体適合、比喩表現、一般的な意味理解を完成条件に加えない。訂正案は任意であり、原句より頻出の表現があることは訂正の必要性を示さない。

## どこで判断が飛躍したか

1. **情報を保持する表現と、検査すべき単位を混同した。** 一部の語と関係を同じkeyへ保存できることから、全2〜4 nodeの未観測を警告候補とした。句読点や助動詞を含む全部分構造が、指摘したい使い方の一件になる根拠はなかった。
2. **参照範囲の不足を、判定機構の不足へ読み替えた。** 速度・保存量の計測用に作った先頭1,000段落・45記事での未観測から、一般的な警告分類が必要とは言えない。
3. **対象外の違いを必須機能へ加えた。** 正用同士の意味差や一般的な多義性から、文脈モデルが必要という話へ広げた。今回の誤用検出に生じた不足の証拠が先に必要だった。
4. **注釈の存在と、対象問題への適合を混同した。** 固定4入力には名詞単体への注釈や「い→いい」「見ますか→見えますか」という訂正があるが、それだけで対象の連語誤用の対照になるわけではない。位置注釈があることを入力選択の根拠にし、何を確かめられる対照かの確認が不足した。
5. **工程への適合だけをレビューした。** 検証コードは固定計画に沿っていたが、計画自体が元の目的を確かめるものかを十分に点検しなかった。

[固定4入力の結果](minimal-validation.md)は撤回しない。ただし、そこでの未観測の広がりを特定の追加機構が必要という結論へつなげた解釈を訂正する。保存済み参照の確認では、対象の二語関係そのものが収録されておらず、存在する同じ関係を索引が失った証拠はなかった。資料を増やせば解決するという結論も、まだ出ていない。

## 今回の比較と残る判断

比較の中心は、原の動詞・形容詞等が、どの語と、どの結び付き方で使われたかである。[比較単位の研究](prior-research.md#語の使い方と列挙できる構造の区別)から、単純な名詞‐格‐動詞型では語彙単位間の関係を核とし、句全体の修飾を一律に一致条件へ足さない根拠を得た。対象の関係を定義することは、照合前に疑わしさを判定して候補を減らすこととは別である。

「つける／つけています」は同じ動詞を使った用例として、既存形態素解析の基本形・代表表記で照合する。元の語を保つことは、助動詞等を含む句全体の完全一致を要求することではない。原文や述語句全体は引用のために保存するが、保存項目を全て照合条件にしない。

格関係と、それが助詞等によってどう記されるかは別の情報であり、動詞の正規化からも分離する。必要なのは同じ出現の語と関係を既存解析から読むことで、独自の助詞対応表や構文補修ではない。狭義の連語に分類されない自由な語の組み合わせも使用実績として参照する。完全な複合述語IDや意味等価判定をこの接続の前提へ加えない。

固定入力・参照表記・結果による判断・予算は[検証計画](lexical-usage-validation.md)に定めた。参照不足と比較条件による取り逃しは、未観測という結果だけでは決めず、原文と公開値まで戻って確認する。未知入力の全文性能は後続で検証し、この対照の成功を一般性能へ広げない。全量処理、警告抑制、追加モデルを先に実装しない。

## 再利用するもの

- 原文位置と公開解析の保存、索引の一致照合、引用と来歴、固定条件での容量・時間の実測。
- [先行研究](prior-research.md)と[解析部品の調査](parser-investigation.md)。研究ごとの課題・出力・限界を保ち、調査済みというだけで部品を必須にしない。
- 固定した評価資料と元注釈。教師訂正文を完全な正用goldとせず、一般的なGEDの成績を対象の連語誤用の成績へ読み替えない。

[構成の記録](architecture.md)は検証済み機構の説明、[工程表](implementation-plan.md)は現在の作業範囲、[セットアップ](setup.md)は既存部品の再現手順である。文脈表現・分類器等の既存コードは、現在の採用構成を意味しない。独自構文規則を含む旧extractorはscratchへ隔離済み。

## 構文解析を修正する前の対象仕様（課題15・案）

2026年10月26日。原の語の使い方を検査するための必要情報を定める案であり、解析器の変更や新しい構成の採用を決めたものではない。既存研究と検証済みの位置対応・索引は再利用する。

### 照合する内容と原文への対応

検査するのは、同じ出現の述語語彙と相手の名詞語彙が、選んだ関係条件で結び付く使い方である。形態素分割と検査する語彙単位を同一視せず、原文位置、語彙内容、活用形、表示に使う範囲を区別する。

- 述語の語彙内容には、サ変の「削除する」「再利用する」の内容名詞も含める。一律に「する」へ縮めず、述語を構成する名詞を相手名詞として一般化しない。
- 活用前の語彙を照合し、活用形・助動詞等を含む原文の範囲は表示と監査のために保持する。保存した全要素を一致条件にはしない。
- 相手の名詞句が原文のどの出現かを保持する。比較する名詞語彙と、その句の全修飾語・指示対象を同一視せず、名詞句全体の完全一致や共参照解析を必須にしない。
- 原の名詞と述語の関係と方向を保持する。別節・別の係り先の語を寄せ集めて一つの使い方にせず、複数条件を比べる場合も参照の同じ出現で成立することを求める。

[Park・Seraku・Kiaer 2016 §2.2](https://doi.org/10.1016/j.heliyon.2016.e00189)は、名詞句全体を取る統語関係と、名詞・動詞の語彙的な結び付きを区別する。[京都大学の公式注釈基準 §2.1・§3.7.6](https://nlp.ist.i.kyoto-u.ac.jp/nl-resource/corpus/KWDLC-1.0/doc/rel_guideline.pdf)は、タグ単位と意味関係を担う自立語部分を分け、動作的なサ変名詞にも項関係を認める。これらは語彙内容と句全体を区別する根拠であり、全複合述語の境界を独自に決める規則ではない。

### 関係条件の範囲

当初の対象は、原文に明示された名詞と動詞・形容詞等の述語との主語・目的語などの結び付きである。それぞれの関係を保って検査する。述語を含む節が名詞を修飾している場合も、節内の対象関係は検査する。ただし、節の被修飾名詞との組を、修飾関係があるという理由だけで新たな検査対象に加えない。目的語が得られたら他の項を捨てる条件ではなく、その出現の関係を選ぶ。解析上の一つの依存辺に限定する意味ではない。

| 確認した文 | 語彙検査の対象 |
| --- | --- |
| このプリセットが名詞・述語を返す | プリセットと返すの主語関係、名詞・述語と返すの目的語関係をそれぞれ検査する |
| 名詞・述語を返すtextlintプリセットです | 名詞・述語と返すの目的語関係は対象。返すからプリセットへの`acl`という辺だけを根拠に追加しない |
| 彼が精度を食べる | 精度と食べるの明示された目的語関係を検査する |
| 彼が食べた精度 | 精度を目的語と推定した検査は、当初の対象への追加になる。節内の関係を取り違えない |
| 精度が高い | 形容詞を述語とする主語関係も対象。動詞だけに限定しない |

同注釈基準§3.5は、連体修飾をガ・ヲ等に対応する内の関係と、それ以外の外の関係に分ける。説明・呼称だけでは内・外は決まらず、構文が成立することも独立した語彙検査の必要性を示さない。現行の`acl`と`head`方向の保持は原構文の保存であり、目的格へ変換している既存バグはない。上の連体文のプリセットを主体と断定しない。

相手の名詞語彙は現行と同じ普通名詞・固有名詞を扱う。「彼」のような代名詞の指示対象を解決し、その対象の語の使い方として照合する機能は加えない。解析器が保持する主語関係と、語彙照合へ渡す対象はここでも区別する。

この対象範囲は、解析器が返せる項目ではなく、後段の支持判定まで含めて判断する。現実装では次の二つは別の照会・別の一般化群になる。

```text
精度を食べる → 食べる / obj / 精度 / dependent
食べた精度   → 食べる / acl / 精度 / head
```

`group_key`は名詞語彙だけを取り除き、依存ラベルと方向を保持する。したがって、前者の用例を後者の目的語として利用する経路はない。配布参照にも`食べる/obj/dependent`と`食べる/acl/head`の群が別々にあるため、後者の照会自体は実行できる。しかし、同じ`acl/head`は食べる側・食べられる側等を区別せず、その照会が適切な語の使い方を評価できる根拠にはならない。構文の保存・照会ができることだけを理由に対象を広げていた点を是正する。

「食べた精度」まで妥当な指摘ができるようになり、解析側だけが未対応だったわけではない。この拡張の可否を利用者の好みとして先に選んでもらわず、必要性と支持判定の成立を別途示してから判断する。今回の修正に格・PAS変換を追加しない。直接の形容詞修飾「高い精度」の扱いも、動詞の連体節に関する確認だけから採用・廃止を決めない。訂正文の候補生成は両形式とも現本体に未実装で、指摘の妥当性とは別である。

### 形式に依存しない語彙単位

名称・識別子は、形態素解析で細分割されても、その内部で独立した日本語述語と相手名詞の用法を作らない。`textlint-rule-preset-native-japanese-0.1.0.tgz`は名前全体を一つの検査語彙単位として扱い、内部の`native`や`japanese`を別々の語彙用法へ分割しない。名前全体が周囲の文章で持つ関係は別に保持する。

同じ表示本文を`.md`と`.txt`で検査した場合、同じ語彙単位・関係を得ることを要件とする。Markdown構文の読み取りと原文位置への対応は入力適応層の役割であり、語彙単位をMarkdownの装飾やコード範囲の有無で変えない。コード内部の自然文を除外する仕様は採用しない。

これは入力形式に依存しない単位の要件であり、全ASCII文字列を一語とする規則や特定の正規表現、NER等の実装方法を決めるものではない。既存解析がこの単位と構成範囲をどう表せるかは未決であり、上記研究が識別子の自動判定を実証したとも扱わない。

### 部品選定と次の判断

必要な出力は、同一出現を指す語彙内容・構成範囲、形態素と検査語彙単位の対応、活用形と原文位置、名詞と述語の関係・方向とその根拠である。特定の解析器の項目名からこの要件を逆算しない。

ライブラリは、これらを公開解析から取得できるか、既存処理を再利用できるかで選ぶ。例が直ったことだけを構成採用の根拠にせず、語彙範囲・原出現・関係が仕様に対応するかと、実用上の費用を確認する。必要情報の不足を独自の構文規則や語別例外で埋めない。

この追記では用例を追加せず、モデルを変更しない。支持判定はBloom陽性または同じ述語・関係条件の用例名詞群との類似度0.35以上で固定し、支持なしの通常errorと処理異常のsystemerrorを維持する。新しい閾値・意味判定・保留状態は加えない。

明示主語・目的語をそれぞれ検査することと、表示本文が同じなら入力形式によらず同じ語彙単位・関係を扱うことは確認済みである。次は、当初の対象に必要な語彙単位・関係・原文位置を既存解析で取得し、同じ出現の照合へ接続する方法を定める。動詞の連体修飾先への拡張を、この修正の前提にしない。対象とその根拠を定める前に、解析器変更や既存の例を直す実験へ進めない。

### 語彙単位について次に確認する仮説

[国立国語研究所の長単位規程](https://repository.ninjal.ac.jp/record/2871/files/LR-CCG-10-05-01.pdf)は、語として働く記号を含む名称やサ変の内容名詞と「する」を、一つの長単位として扱う。[UD Japanese GSDLUW](https://github.com/UniversalDependencies/UD_Japanese-GSDLUW)は、この長単位を依存解析の語とし、基本形・品詞・依存関係を付与する。形態素の細分割から独自に語彙を組み立てる代わりに、この既存単位を用いる仮説を確認する。長単位の定義への適合と、未知の名前をモデルが正しく認定することは別である。

[Stanza 1.15.0](https://github.com/stanfordnlp/stanza/releases/tag/v1.15.0)の公式`gsdluw`既定構成一つを、製品とは別の環境で確認する。公開する語の基本形を一要素のlemma列として既存照合へ渡せるため、内部の短単位解析や別の結合器を足す必要はない。原文の文字位置も公開APIから取得する。モデル本体は依存する学習済み資源込みで約355MBであり、実行環境・メモリ・反復時間は別に測る。

- 先に、明示主語・目的語・形容詞述語、活用・サ変述語、記号を含む名前について、必要な語彙・関係・位置を固定する。既知の誤解析も原因別に原文から選び、モデル出力を見て期待値を決め直さない。
- 名前の内部への指摘が消えただけでは成立としない。名前全体の語彙と、周囲の述語との対象関係が残ることを確認する。Markdownの装飾がない本文にも同じ条件を適用する。
- 公開出力の読み取りだけでこの契約を満たせるかを先に確認し、成立した場合にリポジトリ全文と実textlint経路へ広げる。候補モデル間のスコア競争や閾値調整は行わない。
- 解析の契約が成立してから、保存済みの同じ出典本文を再解析し、正本・Bloom・群平均を再構築する。出典・用例本文の追加はしない。旧解析の索引と混ぜず、正規化契約を更新する。
- 不一致は、語彙境界・基本形・品詞・係り先の予測、入力変換、公開値の接続、用例照会のどこで起きたかを区別する。個別の語や構文の例外で補わず、必要情報が得られない原因に対応する設計へ戻る。

この確認は新構成の採用や検出精度の保証ではない。原文位置・語彙単位・対象関係が保たれることを先に確かめ、用例の支持不足を解析誤りと混同しないための工程である。
