# 目的と現在の判断

AIが出した誤った日本語をリアルタイムで位置付き指摘し、可能なら訂正案を出す。技術文書・一般文を自由文のまま受け取り、不自然な語の組み合わせ・語彙選択を重点に扱う。スクリプトからの自動呼び出し、textlintへの接続、高速な反復実行を必須条件とし、将来の商用利用を考慮する。作者の判定、文体の強制、自動書き換えは対象外である。

## 現在の工程

[課題定義、方式選定、実装の順序](implementation-plan.md)で、必要機能を語彙選択誤り検出・語彙的共起・選択選好・文脈付き意味表現等へ対応付け、[検証する一構成と情報契約](architecture.md)を定めた。現在は、原文位置と構造を保存する接続、用例索引、入力と参照に共通の文脈表現を実装している。検出性能と実利用時の速度はまだ実証していない。

既存手法を一巡してから組合せを考える順序にはしない。目的から必要な情報を決め、既存研究が支える範囲を確かめ、構成の仮説を変える問いだけ検証する。低い総合scoreだけで方式を捨てず、解析・参照資料・一般化・判定のどこで必要な区別が失われたかを見る。設計上分かる欠落を、学習後の誤検出分析へ先送りしない。

## 設計上の制約

- 参照会話の三つ組、名詞側の一般化、コーパス、単語ベクトル、検索、BERTは手段の候補。目的を特定の形式へ合わせて狭めない。
- 形態素・係り受け・述語単位・格の解釈は既存ツールへ委ねる。独自の日本語構文規則や例文別の条件分岐で穴埋めしない。
- 用例を使う場合、原語の使用実績、類似対象からの一般化、資料の量と取得状態を分ける。未観測だけで誤用、意味が通じるだけで正用とはしない。
- 特定分野の使用にも用例としての意味がある。一般文・技術文の頻度差を文体の不適切さへ読み替えない。
- 位置不明・解析不能・保留を自然な日本語と認定せず、未評価として残す。未評価を分母から外して検出性能を良く見せない。
- 原句より頻出の代替があることと、原句を直す必要があることを分ける。訂正案の意味・活用は検出とは別に評価する。
- 精度・速度の数値目標は用途と実測を踏まえて設定する。実験上の比較点を利用者の確定要件として扱わない。

独自構文規則を含む旧extractorはscratchへ隔離済み。公開モデルの限定評価は引き継ぐが、Tohoku＋Oddballnessのそのままの製品採用は見送った。この結果をBERT全般の不可能性とは解釈しない。専用教師を使うこと自体も、Codex等の語彙選択の問題を解決する証拠にはならない。

## 引き継ぐ資料と接続部品

研究の出力・評価対象・利用条件は[先行研究](prior-research.md)、解析器のAPI・実出力・issueは[解析部品](parser-investigation.md)に記録する。目的に合う完成品がないことを開発中止の理由にせず、必要な組合せと拡張を検討する。新しい拡張に未確認の前提があれば、その点の調査へ戻る。

固定seedは`20261021`。寺村の既知全文3,054件を学習者・同一全文で265groupへまとめ、未解決注釈等の318件を理由付きで主比較から除外した。学習1,669文／開発466文／評価601文、語彙spanは1,054／307／380箇所。学習者・group・同一全文の分割間共有は0。補助学習用の教師訂正文は2,933文で、既存dev/test groupと別監査1,000groupを保留する。未注釈位置や訂正文を完全正用goldにしない。

参照資料には2019年2月のWikipediaを固定したMIRACL本文を取得済み。記事IDの固定hashによる抽出を本文・評価例を見る前に定め、同記事のpassageをまとめる。本文抽出の欠落があるため、全て正用の教師とはしない。少量の接続確認を汎用性能の実証には代えない。

再現手順は[セットアップ](setup.md)、原文の文字位置での評価と警告負担のそろえ方は[共通評価器](evaluation.md)、既存の常駐process接続は[textlint](textlint.md)に集約する。これらの部品が動作することと、検出器が目的を達成することは別である。
