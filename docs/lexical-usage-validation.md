# 語の使い方に対応する限定照合

2026年10月22日。実行前の計画。[旧4入力の検証](minimal-validation.md)で未確認だった対象適合と比較単位を見直した。製品の対象をこの二入力へ縮める計画ではない。

## この工程で判断すること

人間が相手語への述語選択を訂正した具体例について、原語の使用実績と訂正語の使用実績を混ぜず、既存解析の値から引用と原位置へ接続できるかを確認する。結果によって、未知入力へ範囲を広げるか、資料・比較条件・解析・接続のどこへ戻るかを決める。全文の検出精度や指摘負担は次の工程で扱う。

比較の核は語彙単位とその結び付きであり、句全体の修飾一致ではない。[Parkほか2016](https://doi.org/10.1016/j.heliyon.2016.e00189)の単純な名詞–格–動詞についての議論と、[公開解析値の調査](parser-investigation.md)を接続する。

今回使う値は、Juman++とKNP係り受けモードの出力をrhoknpで読んだ次の三つである。

- 名詞基本句が所属する文節の `正規化代表表記`。
- その名詞基本句の `係`。
- 同じ基本句の `parent` が指す述語基本句の `用言代表表記`。

公開素性の `体言` と親の `用言代表表記` を持つ関係を読み、値を変更せず一つの出現として保存する。名詞の主辞だけへの縮約、述語の類義語置換、表記の自作分解、助詞・構文の補修はしない。必要な公開値がない箇所を推測で埋めない。

KNPを選ぶ理由は、既存出力で「管理者」の構成語や「正しくする」の述語内容を公開値に保持しており、今回の接続に追加の構文選択規則が少ないためである。GiNZAや他方式が不可能という判断ではない。`畳む` と `畳む〜テ形＋いる` の細分化も残る。これらの値を完全な語彙IDとは呼ばず、不一致を用法の不存在に読み替えない。既知の差を確かめ直す追加例は設けない。

原文・元注釈・元資料の行はGit外の `/workspace/scratch/target-contrasts-20261022.md` に固定した。選定はdevと独立出典だけによる。解析・照合結果、保留testは選定に使っていない。サ変・形容詞・造語・技術文の対象誤用まで検証したとはしない。

## 参照と実行範囲

参照の母集団は取得済みMIRACL日本語Wikipedia2019の記事hash固定5%、56,505記事。ファイルは `selected-buckets-00-04.jsonl`、231,099,796 bytes、SHA-256は `95ce0f55bb3d5bc071168f82232227f4fcabcd184036c16199b10510d36af62c`。本文はCC BY-SA 3.0で、全て正しい文という教師にはしない。入力・述語条件は変更しない。

当初の1%（69,195段落・11,270記事）からは、対象表記を含む9段落・7記事・4,614字を得た。解析前に全9段落の原文を読み、「取り返す」「返す」「渡す」「着用する」等はあるが、今回比較する「ネックレスを着る／つける」の用法はないと確認した。この資料を解析しても狙った対照を得られないため、本解析は行っていない。比較条件や分類器の問題とはせず、既に同じ取得時に固定してある5%へ参照だけを広げる。1%の準備結果はGit外の `lexical-usage-probe-20261022/` に保持し、上書きしない。

この全原文から、本文に文字列 `ネックレス` を含む段落を全件取得する。述語では絞らず、原語・訂正語へ同じ参照条件を使う。選択は今回の検証用の処理量削減であり、未知入力から疑わしい場所を選ぶ機能ではない。表記変種を推測列挙せず、同じ代表値を持つ全用例を網羅したとも扱わない。E1・訂正文・C1を参照に追加しない。

候補の件数・記事数・合計文字数を先に記録し、原文で対照となる用法の有無を確認してから解析へ進む。既存の起動済み1,337字・1.252秒を参考に、推定の3倍＋30秒を予算とし、解析上限を10分とする。概算が上限を超えるなら解析前に予算を見直す。これは処理保証ではない。打切り・解析失敗があれば不完全と記録し、不在を結論しない。全母集団の解析・新モデル取得は行わない。

最小実装はscratch内の公開値読取り、一致照合、引用・位置・来歴の記録に限る。保存済み解析や既存APIを再利用し、専用の永続索引や警告分類器を追加しない。入力二文と選択した参照段落は全文解析する。用言と名詞の各位置を別々に保存し、離れた語の間を誤りspanとして塗り潰さない。元文字列と公開位置が一致しなければ不一致を報告し、独自修復しない。

出力には各原文・出典・解析版、全比較値と参加位置、完全一致した出現の引用、未観測、未処理を区別して残す。参照の未観測について論じるのは `ネックレス` を相手語とする関係に限る。C1の `上着` などを含む全文の未観測件数から指摘負担を算出しない。C1は参照外なので、C1をE1へ引用返却する実験にも使わない。

## 結果から次の判断へ

- **原語と訂正語の支持が分かれる：** 引用の原語・相手語・結び付きと入力位置を確認できれば、この具体例で必要な差を保持できたとする。未知入力・全文へ範囲を広げる計画へ進む。未観測だけで誤用を認定しない。
- **双方が未観測：** 選択した参照の原文と公開値を読む。同じ用法自体がない、用法はあるが比較値が違う、公開解析が別の関係を返す、接続が値を失う、のどれが観測されたかを確認する。独立正用があることだけで参照不足と決めない。
- **原語にも一致用例がある：** 引用が該当する使用実績かを原文で確認する。実績があるなら、この人間訂正例が「用例に裏付けられない使い方」の対照になるかを再考する。今回対象外の正用間の意味差を検出する機能は足さない。
- **関係や位置を失う：** 既存解析の出力と接続結果を照合し、比較設計の不足と実装の不一致を分ける。用例方式全体の否定や別モデルの追加へ飛ばない。

固定入力と選択参照を一度照合し、上のどの判断に進むかを根拠付きで決めれば終了する。結果を見て例を差し替えず、対策をその場で追加しない。実装前のfresh contextレビューでは対象適合と判断の飛躍を点検し、実装後は別のfresh contextレビューで単純さ・既存API利用・不要なテストを確認する。

未知入力の全文検出、名詞未収録への対応、訂正案、Unicode・Markdown全般、実利用速度・容量、辞書・モデルの配布条件は後続工程に残る。この検証を通過しても製品の完成とはしない。
