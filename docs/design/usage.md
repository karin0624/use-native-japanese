# 語の使い方の照合

## 目的と対象外

原文の語と関係を用例へ照合し、支持のない使い方を指摘します。リアルタイムの位置付き指摘を目標に、スクリプト・textlintから利用し、商用利用も想定します。

試作の完成条件は、所定形式の情報追加による改善と規模拡大、容量・構築・検索費用の増え方を示すことです。全件正答や全用例の収録は求めません。

正用同士の意味差、AI生成の判定、分野ごとの文体は扱いません。訂正候補は未実装です。

## 入出力

入力は日本語本文、出力は照合する両側の原文範囲とメッセージです。

| 結果 | 出力 |
| --- | --- |
| 用例による支持あり | 指摘なし |
| 支持なし | 書き手への通常のerror |
| 解析・資源・通信などの処理異常 | systemerror |

支持なしは参照資料での判定であり、日本語全体での不存在を証明しません。

## 恒久仕様

- 原文全体とGiNZAが返す全解析情報を`Analysis`に保持します。各判定機へ同じ`Analysis`を渡し、各判定機はその全情報から必要な情報を参照します。局所的な比較範囲は元データへのviewとして別に示します。
- 構文解析、構成の同定、関係の認定は静的に行います。
- 述語は構成を含めて用例にあることを必須とします。ただし、次項の根拠による異構成の用例流用を認めます。「畳む」と「畳ませる」は異なる構成として照合します。
- 将来、言語の構文から当該文で両方の構成が使えると静的に確定できるなら、いずれかの用例で支持してよいものとします。その構文上の根拠を明示し、元の成分を保持したまま適用します。
- 類似度は厳密なP・役割・方向・接続点が一致する実共起群内のN比較だけに使います。P–P関係は厳密な実共起群の存在によって判定します。
- 照合規則は例文をまたいで共通に適用します。
- この仕様に反する案は直ちに不採用とします。

## 解析と比較範囲

[Parser](../../src/native_japanese/parser.py)はGiNZAのC分割後、ASCIIの連続英数字・英字等から始まる識別子を元Token境界に合う範囲で結合し、同じDocを解析します。NERは解析対象外です。Tokenの境界と品詞には、このパイプラインの解析結果を使います。

`Analysis`は原文全文、公開`Doc.to_bytes()`のsnapshot、復元に必要な語彙情報を保持します。Tokenの文字位置・lemma・UPOS・XPOS・形態情報・元依存辺、GiNZAの文節情報、Docのtensorを保存し、Vocabのstrings・vectors・lookups・Lexeme状態も復元用に保持します。固定モデルの全Vocabを基底として一度保持し、解析に伴うstrings・Lexemeの追加と変更、vectorのkeyの追加・変更・削除、行・shape・dtype・実値とVocab設定の変化を、親を参照する不変の差分世代として共有します。各文書は解析時点の世代を参照し、解析済みの他文書に由来するVocab情報も含めて保持します。`restore_doc()`は語彙を含めて独立したDocを復元し、vectorの次元・値を保ち、復元した各Docの語彙は個別に変更できます。保存形式は[API仕様](../reference/runtime.md#用例jsonl)で定義します。

`UsageJudge`は`Analysis`を受け取り、[UsageStructure](../../src/native_japanese/comparison.py)で元Token IDを参照する局所viewを作ります。このviewは用法照合で必要なToken・依存関係・文節・lemma・Lexeme属性を参照します。比較範囲の同定・照会・対応検証はこの判定機の内部で行います。

### 出現と役割

用法照合で評価する辺を選ぶ前に、元解析から次の述語役割を認識します。この選択規約は、固定した解析版における判定機の用例照会範囲を定めます。

- `Inflection`と動詞・形容詞・形状詞のXPOSを持つ語。ただし、文脈上のUPOSが`AUX`・`SCONJ`・`ADP`・`PART`・`CCONJ`、または元依存関係が`aux`・`cop`・`fixed`・`mark`・`case`・`compound`である語は、この根拠では認識しません。
- `csubj`・`ccomp`・`xcomp`・`advcl`・`acl`の従属側、`amod`の形容詞側。
- `advmod`の従属側で文脈上のUPOSが`VERB`・`ADJ`である語。
- `ROOT`・`conj`・`parataxis`で、UPOSが`VERB`・`ADJ`、またはXPOSの先頭分類が動詞・形容詞・形状詞である語。
- 主語・目的語・斜格項・補語を支配するhead、`advcl`で節修飾を受けるhead、`aux`・`cop`のhead。

役割の証拠は、選択した元Tokenと、根拠の辺・UPOS・XPOSに対応付けます。名詞を核とする述語を含め、上記の条件を満たす語を述語として認識します。

### 述語構成P

Pは、核と述語的な機能単位の直接用例照合に使う原解析上の参照範囲です。語形成、補助構成、名詞化・節接続の元役割を保持して静的に定めます。

| 元解析上の条件 | Pへの参照 |
| --- | --- |
| `aux`・`cop` | 述語の機能要素として接続 |
| `compound` | 複合語の構成として接続 |
| 同文節内の`fixed` | 一つの固定機能表現として接続 |
| `mark`の`fixed`機能単位に、文脈上のUPOSが`VERB`・`ADJ`・`AUX`である従属語を含む | 同文節内でPへ接続 |
| 同文節内の`acl`・`advcl`・`amod`で、両端が`VERB`・`ADJ`・`AUX`、かつ一方のXPOSが動詞-非自立可能 | 補助的な述語構成として接続 |
| 同文節内の`nummod`で、headが接尾辞、従属語が`NUM` | 助数の語形成として接続 |

接続した元辺を両方向に参照する成分がPです。根と、評価辺が接続する語は別に保持します。`nmod`や文節境界は、Pの構成を広げる根拠の対象外です。

「走るのが」の`の`は名詞化標識であり、内側Pは「走る」です。「読んでいる」「かもしれない」「のではない」の固定機能単位はPの構成に残します。「ために」「にしても」「につれて」「に従って」は節接続の参照を持ちます。後者のうち、GiNZAの文脈上のUPOSが`SCONJ`である語は、節接続として扱います。「ので」では`の`（mark）と`で`（fixed/AUX）をP側でも参照し、節接続の役割を保持します。各Pの`marker_units`は、Pへの参照の有無と別にmarkとそのfixed機能単位を保持します。語の構成と活用は解析属性から判定します。

Pの厳密キーは、成分根・相対語順・各語のlemmaとXPOSと`Inflection`・内部辺の接続先とラベルです。根の外部接続先とラベル、UPOS・Reading・絶対Token IDは原Docへ保持します。活用情報が異なる構成は別のキーになります。

### 評価辺と関係の型

Nは、項・修飾対象、または外側で項や修飾として働く節の表現です。名詞化された節など、文脈中で名詞表現として働くまとまりも含みます。両端が述語として働く関係はP–Pとして照会します。

| 元依存関係 | Pの接続先 | 反対側の根 | 照会する役割 |
| --- | --- | --- | --- |
| nsubj・csubj | head | dependent | nsubj（主語） |
| obj・iobj・obl | head | dependent | 元の役割 |
| ccomp・xcomp・advcl | head | dependent | 元の補語・節修飾の役割 |
| acl・amod | dependent | head | 元の修飾の役割 |
| advmodの語彙的述語 | headが認識済みPならhead、それ以外はdependent | Pの反対側 | advmod（元の修飾役割） |

`csubj`と`nsubj`は主語の表現形式をまたいで共有します。`ccomp`・`xcomp`は補語の制御などの区別、`advcl`は節修飾の接続を保ちます。GiNZAが名詞化節を`advcl`にした場合は、その役割で外側の組合せを照会します。`advmod`の「走ろう」のような語彙的述語も、外側接続と内側Pを照会します。修飾先がPでない場合は、名詞表現として働く根拠がある対象だけをN側にします。非名詞・非Pの修飾先は対象外の理由を保持し、元解析を`Analysis`から参照できます。Pの認識には[出現と役割](#出現と役割)の条件を適用します。全ての元ラベル・方向・接続点はviewへ残します。反対側の根が認識済みのPに含まれ、名詞化節・`csubj`・活用による述語役割のない名詞等を核とする逆向き修飾対象に該当しないときはP–P関係にします。名詞化節の外側はNとして扱います。

構成内部の辺は組合せの対象と区別し、空白・句読点の端点は対象外の理由を保持します。Nの元subtree全体と内部辺を保存した上で、特徴viewを分けます。

- N内部の`case`とその`fixed`機能単位は格標識として参照し、語彙特徴の対象外とします。「父に」「父から」の比較対象は共に「父」です。N根自身の外部接続がcaseでも、Nの語彙核は特徴に含めます。
- 逆向きの修飾関係では、評価中のP接続語を根とするsubtreeを特徴から外します。
- 残る範囲の空白・句読点以外の全lemmaを`Vectors.compose`へ渡します。名詞化標識・修飾句・内部Pもこの範囲にあれば含めます。

名詞化標識とN内の述語出現も元Tokenへ対応付けます。「走るのが好きだ」の外側Nに「走る」が含まれても、内側Pの厳密照合は別に行います。Tokenの分割と依存関係は原解析に対応付けて保持します。

端点は各側の元Tokenの文字範囲です。連続しない範囲は別々に示し、表示文字列は先頭から末尾までの原文です。

## 支持判定

解析契約の識別子と固定版は[models.py](../../src/native_japanese/models.py)、交換形式は[API仕様](../reference/runtime.md)で定義します。照合は入力と参照に同じviewを適用します。

1. 全てのPを厳密な述語索引へ確認します。P単独の照会は、そのPの存在だけを判断します。
2. P–P関係は、両Pの全構成・`Inflection`・内部辺・根、双方の接続点、元の役割と方向が完全一致する実共起群をSQLで照会します。群が存在するときだけ`indexed`とします。
3. N–P関係は、P・P内の接続点・対応付けた役割・Nの方向が厳密一致する実共起群を確認します。群がなければ`review`とします。
4. N–Pの群があれば、Nのlemma列も含むキーがBloom陽性なら`indexed`にします。陰性なら、群内の異なるN特徴列を等票で平均したベクトルと入力Nを比較し、cosineが境界以上なら`supported`にします。
5. 支持がなければ`review`として原文位置を指摘します。

認識した各P・各関係から照会への対応、接続点・役割・N特徴を検査前に検証します。対応の欠落や空照会は処理異常です。各Pと各関係を個別に判定し、その結果を全て集約します。空文・空白・通常の名詞句など、正当に対象がない入力は無指摘です。

既定境界は0.35です。これは名詞側の近似比較だけに使います。平均はNの語彙特徴を語順によらず近似する値です。比較はP・接続先・関係・方向が一致する群内に限ります。ベクトルを取得できない場合は、類似度を未算出として追加支持なしとします。資源破損・非有限値・解析契約の不一致は処理異常です。

## 根拠と制約

文節の取得は[GiNZA](https://megagonlabs.github.io/ginza/)、原解析の保存はspaCyの公開[Doc直列化](https://spacy.io/api/doc#to_bytes)と[Vocab直列化](https://spacy.io/api/vocab#to_bytes)を使い、直列化だけに含まれないLexeme属性も別に保持します。[UD日本語の名詞化節](https://universaldependencies.org/ja/dep/csubj.html)、[aux](https://universaldependencies.org/ja/dep/aux_.html)・[cop](https://universaldependencies.org/ja/dep/cop.html)・[compound](https://universaldependencies.org/ja/dep/compound.html)・[fixed](https://universaldependencies.org/ja/dep/fixed.html)の役割と元解析を接続の根拠にします。構成辺は、核と元役割を区別した、この固定解析版の静的な用例参照規約です。支持推定の研究上の位置付けは[先行研究](../research/prior-research.md)を参照してください。

元解析の係り先やlemmaの取り違えは残ります（[#21](https://github.com/karin0624/use-native-japanese/issues/21)、[#22](https://github.com/karin0624/use-native-japanese/issues/22)）。構成と活用が厳密一致しない正用は参照を共有できず、異構成を静的に推論する機能は未実装です（[#30](https://github.com/karin0624/use-native-japanese/issues/30)）。一般の名詞同士の修飾関係は評価対象外です。

N–PのBloom陽性には、厳密に存在する群の内側で低確率の誤通過があります。群平均とのcosineと境界は名詞側の近似比較に使う指標で、正誤の確率を表す値ではありません。用例追加で判定が悪化する場合もあります。表記差とベクトルの取得範囲により正用を支持できない例があります（[#23](https://github.com/karin0624/use-native-japanese/issues/23)、[#24](https://github.com/karin0624/use-native-japanese/issues/24)）。
