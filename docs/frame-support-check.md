# 用法群内の平均による支持の確認

## 判断する仮説

[名詞類似度の最大値](nominal-support-check.md)では、「着る＋ネックレス」が辞書の指輪から、「しめる＋電気」が水道から強い支持を得た。支持元の読取りは確認済みだが、自動収集された用例の正しさは保証されない。次は**一名詞への依存を弱めながら、通常使用に近い用法群の支持を残せるか**を確認する。平均で参照の誤りや名詞の意味表現が直るとは考えない。

[Erkほか2010](https://aclanthology.org/J10-4007/)の式(6)・UNI設定は、観測された名詞との類似度を等重みで平均する。[Greenbergほか2015](https://aclanthology.org/N15-1003/)は、一つの近い名詞への依存と、異なる用法を一集合へ混ぜる問題に対し、群内の平均と群間の最大を組み合わせる。ただし同論文の正規化した重心とのcosineと、ここで使う符号付きcosineの平均は異なる。

[京都格フレームの構築研究](https://nlp.ist.i.kyoto-u.ac.jp/member/kawahara/paper/NLP-CaseFrame2.pdf)では、用法の異なる用例を分けてまとめる。[公開consumer](https://github.com/ku-nlp/knp/blob/bc4cef188669f88cdeb590fe7afb1021ce2ae481/system/case_analysis.c)も、通常frameと、それらのORである和フレームを区別する。この既存のまとまりを再利用し、新しいクラスタリングは行わない。frameは人手で保証された語義群ではなく、小群や群全体の誤支持は残り得る。

和フレームの一括平均は異なる用法を混ぜるため、今回maxを選んだ「少数の通常使用を平均で消さない」という意図も踏まえ、**通常frame内のUNI平均、frame間のmax**を一案として固定する。二方式を試して結果のよい方を選ばない。関係付き名詞プロファイルは別の情報を加える案として保持し、今回の集約確認より先には追加しない。

## 計算と入力の契約

1. 原述語・型・格、F/N等の照会候補、単純名詞・複合名詞の取得方法は前回のまま。既存の通常frameの同じ格だけを使い、和／通常はheaderの明示flagで区別する。番号から推測しない。
2. 一つのframe・格内では、頻度を除いた実語ID列を一単位とする。複合は全ID列の順序を維持し、同一単位の重複表示を一票にする。別frameの頻度や票を足し合わせない。
3. 一単位に複数の表記候補がある場合は、比較可能な候補のcosineを平均する。同じIDの表記に等しい重みを置く仮定を明記する。alias数で票を増やさず、aliasの最大値も採らない。既存の各候補のベクトル作成は変えない。
4. frameの支持は、比較可能な実語単位の支持の等重み平均。負値は切らず、平均ベクトルの再正規化もしない。入力への支持は、採用された全照会の通常frameのうち最大の値とする。
5. 未接続の`?`、特殊属性ID、欠損成分、非有限・ゼロベクトルは名詞やゼロ類似度へ変換しない。全単位数、比較可能数、候補不能とその理由を保存する。不能を除いた平均は比較可能集合内の値であり、全frameの平均とは呼ばない。
6. 通常frameがない、又は全単位が不能なら未計算とする。和フレームへの暗黙のfallback、語別除外、最低頻度・最低群サイズ、top-k、閾値探索は加えない。

直接収録された使い方は従来どおり近傍計算を省略して別に保持する。ただしこれは自動解析上の観測であり、正用ラベルではない。今後の独立評価では、その非指摘経路による見逃しも結果へ含める。

保存19照会の324recordを限定再読し、長さとhashは全件一致した。型一致の和は15、通常は282。今回、和なしでrecordのある照会は通常1frameの「絞める」だけだった。近傍計算対象11照会の`?`なしIDには逆引きaliasの不足がなかった。直接支持で省略した4照会には逆引き未取得のIDがあるため、その近傍計算へ範囲を広げない。

## 実施範囲と記録

前回の固定9関係、保存token・alias・照会情報、同じ約22MBモデルと固定依存版を使う。辞書の再走査、全文の再解析、別モデル・コーパスの取得は不要。frameの明示flagは、限定再読で確認した保存metadataを使い、その入力hashも固定する。

実装はscratchに置き、既存のベクトル取得と汎用数値ライブラリを再利用する。fresh contextで重複・分母・不能処理と小fixtureをレビューしてから、一度だけ比較を実行する。上限は5分。固定metadataを繰り返し保存する仕組みは追加しない。

出力はframe別の平均・単位数・取得不能数、各単位の支持と重み、最大frameと支持名詞、前回maxとの対応、処理時間・RSSを保存する。一語frameや、不能により実質一語となったframeを隠さない。原文・辞書・モデルはGitへ入れない。

## 結果による判断

平均は最大値より下がりやすいので、対象誤用の値が下がっただけでは改善としない。通常使用の支持が残るか、対象誤用への過剰支持が相対的に弱まるか、その変化をどのframe・名詞が作ったかを確認する。9例全ての分離や共通閾値の存在は進行条件にしない。

残った失敗は、少数語だけの最大frame、同群の多くの語による話題的支持、通常使用の支持の希釈、取得不能に分ける。結果に合わせた語や群の除外は行わない。個別の失敗を方式全体の否定にも、個別の成功を完成にも使わない。

有用な支持が具体的に残り、集約の効果と限界を説明できれば構成を固定し、既に選択済みの独立した人手訂正9対と全文で対象の検出・通常使用への指摘・原文位置を確認する。訂正対の順位だけを全文検出性能としない。今回の結果から製品閾値を選ばず、必要な調整と独立評価を分ける。

調査とfresh contextの設計レビューはGit外の`selectional-aggregation-design-20261022.md`、`caseframe-aggregation-contract-20261022.md`、`aggregation-goal-review-20261022.md`に保存した。
